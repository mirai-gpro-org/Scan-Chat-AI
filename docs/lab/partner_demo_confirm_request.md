## 0. この文書の使い方

- **§1 が LAiF 宛、§2 がプリベント宛**。文面は同じ骨格で、違うのは「対象検査・ファイル・確認事項」だけ。

LAiF 株式会社

平素より大変お世話になっております。株式会社ウェルフォートでございます。

AI疾病発症予測のデータ受け渡しについて、**ポータル画面のデモ**をご用意いたしました。

■ ① デモ画面
　URL：https://www.wellfort.co.jp/partner-portal-preview?partner=laif

■ ② アクセス方法について（重要）
**本番ではパスキー（生体認証）によるアクセス管理を行いますが、今回は画面をご確認いただくためのデモですので、認証は設定しておりません。上記 URL をそのまま開いていただけます。**

■ ③ ファイル形式のご確認（今回いちばんお願いしたい点）
デモ画面の「入力ファイルを取得」から、**弊社からお渡しする入力ファイルの実物（ダミー記入版）**をダウンロードいただけます。
以前ご案内していた弊社独自の CSV ではなく、**貴社の正式フォームに統一いたしました**。下記の認識で相違ないか、ご確認をお願いいたします。

1. **様式**：貴社正式フォーム `input_format_new_202312.xlsx`（No.0〜157・約158項目）をそのまま使用します。
2. **名前欄**：「空欄だと解析できない」とのご指摘を受け、**氏名ではなく識別番号（整理番号）**を記入いたします。**実際のお名前は記載いたしません。**
3. **識別番号（整理番号・No.0）**：**弊社で採番する 10 桁の仮名 ID**（例：2026000123）を用います。貴社側での採番は不要です。この番号で検体とデータを突合いただく想定です。

あわせて、項目名・桁数・記法（定性の `(ー)` `(±)` `(1＋)` 等）に読み替えの不都合がないか、また**弊社側で埋めるべきなのに空欄になっている項目**がないか、お気づきの点をご指摘いただけますと幸いです。

■ ④ 今後の流れ

## 4. PDF 化の手順

```
node scripts/build-partner-request-pdf.mjs            # 差出日＝実行日
node scripts/build-partner-request-pdf.mjs --date 2026-08-25   # 差出日を固定する場合
```

| 生成物 | 内容 |
|---|---|
| `docs/lab/partner_demo_confirm_request_laif.pdf` | §1（LAiF 宛）だけを 1 通の手紙として組版（A4・2 ページ） |
| `docs/lab/partner_demo_confirm_request_prevent.pdf` | §2（プリベント宛）だけを 1 通（A4・2 ページ） |

- **md 全体は PDF にしない**。§0／§3（社内メモ）／§4／§5 は社内用なので、スクリプトは
  **各セクションの「### 件名」「### 本文」だけ**を抜き出す。md 側でこの見出し構造を変えると
  スクリプトは**エラーで止まる**（黙って空の PDF を出さない）。
- 組版は日本語の書式に合わせ **日付（右）→ 宛名 → 標題（罫線囲み）→ 本文** の順。
- **和文の `**強調**` は `boldJa()` で先に `<strong>` へ変換している**。CommonMark の
  right-flanking 規則では「**…（ダミー記入版）**を」のように**約物の直後で閉じる `**` は
  閉じ記号として扱われず**、`**` がそのまま PDF に出る（実測 2026-08-25・LAiF 宛 ③ で 3 箇所）。
- Playwright 同梱の Chromium が無い環境では `CHROMIUM_PATH=/path/to/chrome` を付けて実行する。
