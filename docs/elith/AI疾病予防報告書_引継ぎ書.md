## 1. この機能は何か（1 段落）

Elith から受領した JSON を**可読化**して本人に見せる報告書。
**フォーマット変換ではない。** Elith の出力は文章の羅列で一般ユーザーが読み通せないので、
**出す文を選んで構造に置き**、選ばれなかった文は全編に畳んで置く。
実測: 受領本文 20,046 字 → ダイジェスト 1,478 字（削減率 **92.6%**）。

サービスの 2 本柱 = **A 初期がんの早期発見 / B AI 診断による疾病予防アドバイス**。
本報告書は **B のみ**を担う。年 4 回発行され、**回によって材料が違うので
「材料が無い章は出さない」が第一級要件**。

## 2. 越えてはならない線（これを破ると作り直しになる）

1. **Elith の出力 JSON に無い文言・表現を一切使わない。**
   要約・言い換え・順位づけ・判定の生成は全部禁止。**紙面に出る全文が受領 JSON の部分文字列**
   であることを回帰チェックが機械で確認している（例外は `PILOT_CANCER_FINDING_TEXT` 1 つだけ）。
2. **見本 PDF は「様式のお手本」であって「埋める項目の一覧」ではない。** 枠は借りる。中身は借りない。
   **型を先に置くと、埋めるために中身を作ることになる。**
3. **紙面を変える手順は モック → 契約再生成 → 実装 の順だけ。**
   契約 JSON を手で書き換えて通すのは禁止。
4. **「要注意」という語を使わない。** 赤は救急サインだけ。
5. **LLM を後段に入れない。** 効果が実質 1 件で、得意領域が全部禁止事項と重なる（仕様書 §5.5 の条件を満たすまで）。
6. **決裁台帳（仕様書 §6）の項目に、実装で答えを出さない。**

**要望は 3 分類で仕分ける** — (a) 見せ方＝設定 / (b) 構造＝コード追加 / (c) 内容の創作＝不可。
**(c) を (a)(b) のふりで受けない。**

## 3. コードの地図

```
受領 JSON ──► report-adapter.ts ──► report-model.ts ──► report.astro
              (変換規則を所有する      (型。画面はこれ      (画面と ?print=1 が
               唯一のモジュール)        しか知らない)        同じレンダラ)
                     ▲                                          ▲
        elith-report-queries.ts (DB→アダプタ)      report-sections.ts (章レジストリ /
                     ▲                              2 本柱 REPORT_AXES / app_config 上書き)
        api/admin/elith-report/upload.ts (取込・Bearer ADMIN_API_KEY)
        api/admin/elith-report/audit.ts  (抽出監査)

        save-steps.ts (「手元に残す」の端末別 手順。手順は公式の一次資料から起こす。
                       app_config `ui.save_steps` で語だけ差し替え可)
```

**3 層を壊さない。** Elith の形式は世代ごとに変わる（実際に `判定区分` と `[pN]` が消えた）ので、
**アダプタ 1 枚で吸収する**のが設計の要。

### 変更してよい場所 / いけない場所

| したいこと | 触る場所 |
|---|---|
| 章の順序・表示可否・見出し・開閉を変える | **app_config `report.sections.*`**（コードを触らない・admin から即時） |
| 受領形式の世代差を吸収する | `report-adapter.ts` **だけ** |
| 章を足す | `report-sections.ts` の `CHAPTER_REGISTRY` ＋ モック ＋ 契約再生成 |
| 紙面の見た目 | `global.css` の `.report-sheet` ブロック（**`tailwind.config.mjs` の `brand` は変えない**） |

## 6. 詰まったときの切り分け（**推測しない**）

```
GET https://scan-chat-ai.vercel.app/api/debug/viewer?k=<PROBE_UPLOAD_TOKEN>
```

`report` ブロックが「なぜその紙面になっているか」を 1 回で答える。

| 出力 | 意味 |
|---|---|
| `demo_enabled: false` | デモが出ていない → 紙面は `emptyVM`。**admin かどうかは無関係**。この uid をデモ用アカウントに登録する |
| `shape: 旧形式` かつ `demo_enabled: true` | 現行サンプルへ差し替わる（正常） |
| `chars < 2000` | **紙面が薄いのは実装ではなく行の中身** |
| `matches_mock_shape: true` | サーバの紙面はモックと同形。違って見えるならブラウザ側かURL |

**`?u=` が付いていないか必ず確認する。** 代理表示中は相手の実データを見せる設計なので、
相手がデモ用アカウントでなければ紙面は空になる。**2026-08-30 にこれで 2 時間溶かした。**

**行の有無だけを見て「データは在る」と判断しない**（仕様書 §4.5.1）。
