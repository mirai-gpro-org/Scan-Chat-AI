# この仕様書の構造 — なぜ普通の仕様書と違うのか

**この機能は 2 回、実装が紙面と違うものになって作り直しになった。**

| 回 | 何が起きたか |
|---|---|
| 1 回目 | 受領本文をそのまま流した。画面 20,297 字 / 受領 20,490 字 = **削減率 1%**。全リバート |
| 2 回目 | ダイジェストを作ったが、**モックと照合しないまま本番へ**。検査値の並びがモックと違っていた |

**2 回とも直接の原因は同じ: 仕様書の散文を読んで実装し、モックを見なかった。**

そこで本書は **紙面のことを一切書かない。**

> ## 【最重要】紙面の正はモックであり、この仕様書ではない
>
> - どのカードが / どの見出しで / どの文を / どの順で 出るか — **すべてモックが持つ**
> - **本書にそれを書き写さない。** 書き写すと「もう一つの正」ができ、実装者がどちらかを選ぶ。**それが 2 回の失敗の正体**
> - 本書が定義するのは **正の所在・素材・変更手順・検証・未裁定** の 5 つだけ

## 4.4 端末に残す（オフライン）【確定・発注者判断 2026-08-28 / 実装済み 2026-08-30】

**オフラインで見たいのは「AI疾病予防報告書」だけ。アプリ全体のオフライン化は対象外。**
理由 = 他の検査報告書は**紙でユーザーの手元に届く**が、これは**アプリからしか入手できない**。

### 手段 A（正） — 端末のファイルとして残す

`?print=1` の紙面 → 共有 → プリント → PDF →「ファイル」アプリへ保存。
ブラウザのストレージの**外**に出るので、iOS の ITP によるストレージ破棄で消えない。
画面には独立導線（`?save=1`）で手順を出す。主要利用者は 50〜65 代なので、共有シートを
自力で辿らせない。

**保存された控えは更新も回収もできない。** だから紙面に**作成日と版**を必ず印字する
（実装済み = 表紙の「作成日」「紙面 v1.0」）。消せると誤解させる UI を作らない。

### 印刷ビュー `?print=1` は `@media print` に依存させない【重要】

iOS には 共有→**プリント**（印刷 CSS が効く）と 共有→**PDF**（効かない・こちらが見つけやすい）の
2 経路がある。後者では**折りたたんだ本文が PDF に載らない＝中身が欠ける**。

→ **`?print=1` は別実装ではなくモード引数**。全展開・UI なしを**通常の画面 CSS で**出し、
`@media print` は上乗せに留める。**どちらの経路でも同じ紙面になる。**
**`?print=1` では折りたたみを使わない。**

- 手順そのものが PDF に載ってしまうので、**保存手順（`?save=1`）は印刷ビューに置かない**
- iOS・Android の実機確認は未実施（WebKit は手元で再現できない）

### やらないこと — **Service Worker で報告書をキャッシュしない**

| # | 理由 |
|---|---|
| 1 | `/report` は **SSR**。キャッシュすると**認証を通さずに HTML を返す**ことになり、端末のロックが解ければ他人の結果が読める |
| 2 | iOS のストレージ破棄の扱いが読めない（Apple 側の変更が続く領域・記憶を根拠にしない = R3） |
| 3 | 実装量が大きい。**報告書 1 点を残すだけなら手段 A で足りる** |

### ただし最小の SW は入れる【実装済み 2026-08-30】

`manifest.webmanifest` が `display: standalone` なので、SW が無いと**ホーム画面起動時に
「アプリの見た目のままブラウザのエラー画面」**が出る。**それを 1 枚の案内に差し替えるためだけ**に置く。

| ファイル | 役割 |
|---|---|
| `public/sw.js` | ナビゲーション要求だけを見る。**必ずネットワークが先**で、失敗したときだけ案内を返す |
| `public/offline.html` | 案内 1 枚。**キャッシュされる唯一のファイル**なので、個人のデータを 1 文字も置かない。CSS もインライン |
| `src/layouts/BaseLayout.astro` | 登録。失敗しても画面は壊さない。`?sw=off` で登録解除できる（実機の逃げ道） |

- **ネットワーク応答をキャッシュに入れない。** 保存するのは `offline.html` だけ
- **ナビゲーション以外は横取りしない**（API・CSS・JS・画像は `respondWith` を呼ばない＝挙動不変）
- **実測（2026-08-30・Playwright）**: 登録 = active ／ キャッシュの中身 = `/offline.html` **1 件のみ** ／
  オフライン遷移 → 案内が出て**検査データの語は 0 件** ／ オンライン復帰 → 本物の紙面が出る
  （キャッシュを返し続けない）／ 非ナビゲーション要求は素通し ／ `?sw=off` で登録数 1 → 0

## 4.6 誰にダミーデータを出すか【確定・発注者指示 2026-08-30】

> 「**admin の管理者リストにあるメンバーだけ**は、現状と同じテストのダミーデータを表示する
> モードにして、他のユーザー（Google 認証でログインして顧客DBに登録があって、admin の
> 管理者でないもの）は、**正規に自分のデータしかアクセスできないように本番設定に**して」

| 閲覧者 | ダミー | 実データ |
|---|---|---|

### 実装（`demo-data.ts` `demoFallbackEnabled`）

**順序が要件そのもの。**

```
① admin なら true            ← env で塞がない
② env PUBLIC_DEMO_FALLBACK === 'false' なら false   ← admin 以外を一括で切る
③ DEMO_ALLOWED_UIDS
```

**旧実装は ① と ② が AND（②が先）だった。** そのため本番で `PUBLIC_DEMO_FALLBACK=false` を
入れると **admin まで塞がれ**、`/report` が `emptyVM`（主軸の帯と主軸 A の 1 枚だけ）になっていた
（実測 2026-08-30・§4.5）。これでは `13a8a95` が宣言した「デモ表示を**admin 限定**にする」の
admin 限定の枝が本番で死ぬ。→ **admin を先に見る**。

### すでに入っていたもの（総合テストのセッション・`13a8a95`／実測 2026-08-30）

- **全ユーザー向けページ 9/10 が `resolveViewer` を通る**（残る 1 つ `index.astro` は

### admin 判定は email からも成立する【2026-08-30・追加】

> **本番の `/report` が空のままだった。** 修正は入っていた（PR #189）が、
> **admin 判定の実体が `ADMIN_MEMBERS` の uid だけ**だったため、
> **登録簿に載っていても admin にならない経路が 2 つ**あった。

**確かめられた事実はここまで**（`/report` が `emptyVM` になり、氏名は出ていた
＝ `data` は解決済み ⇒ `diagnosticUserId` は実在）:

admin になれない経路は 2 つあり、**どちらでも同じ症状になる**:

| # | 経路 | 内容 |
|---|---|---|
| ① | **uid 未登録** | 登録簿に email では載っているが uid が `null` |
| ② | **uid が古い** | ハードコードの uid が**本番の実値と食い違っている**。uid は手で書き写したもので、顧客DBの採番と一致している保証が無い |

**下の対処は ①② の両方に効く**（email が登録されていれば uid を一切見ない）。
**どちらだったかは `/dashboard` のデバッグ欄が答える**（下記）。

**サインイン時に、サーバで検証済みの email から admin を判定し、署名付き Cookie に載せる。**

| | |
|---|---|
| 判定の場所 | `api/auth/resolve.ts` — `signViewer(uid, isAdminEmail(email))` |
| email の出どころ | `sb.auth.getUser(accessToken)` で**サーバが検証した値**。クライアントの申告ではない |
| 改竄耐性 | admin フラグを payload に含めて HMAC を取る。`0`→`1` に書き換えると**署名が合わず弾かれる** |
| 旧 Cookie | `uid.exp.sig` の 3 分割も**受ける**（`admin:false` で復元し、uid リストで補う）。発行済み Cookie を一斉に無効化しない |
| 成立条件 | `viewer.isAdmin = Cookie の admin` **または** `uid が ADMIN_MEMBERS.uid に在る` |

**これで `ADMIN_MEMBERS` に email を 1 行足すだけで admin として扱える**（uid を調べる必要がない）。
uid も埋めておくと `?u=` 入場など Cookie 以外の経路でも admin になる。

**閲覧者フラグは画面から判定関数まで引き回す。** `demoFallbackEnabled(uid, viewerIsAdmin)` の
第 2 引数は**任意**なので渡し忘れても型では落ちない → `verify:demo-gate` が
**渡し忘れを機械で検出する**（入口 4 モジュール ＋ ページ 5 枚 ＋ `resolve.ts`）。
**代理表示中（`?u=` で他人を見ている）は渡さない** — 相手の実データを見せるため。

| **admin（email 登録のみ・uid 未登録）** | **42** | 出る |

| 一般顧客が admin フラグを改竄 | 1 | **0** |

  片方だけ直して通すのは契約の放棄

| `npm run verify:report-model` | 逐語であること・削減率・捏造ゼロの境界・**受領形式の世代差** | 不要 |
