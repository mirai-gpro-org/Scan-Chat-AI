## この文書の使い方 — 最初に読む

**この文書は、読み手が違えば違う結論になる、ということが起きないように書いてある。**

過去に 2 回、実装が仕様から外れて作り直しになった。原因は「機能の説明が 20 本以上の
ドキュメントに散らばり、各人が違う部分だけを読んで、読んでいない部分を推測で埋めた」こと。
そこで本書には次の 4 つの規律を置く。

### 規律 1 — すべての記述に【確定】か【未裁定】のラベルが付く

| ラベル | 意味 | 実装してよいか |
|---|---|---|
| **【確定】** | 決まっている。出典がある | **してよい** |
| **【未裁定】** | 決まっていない。競合する記述が複数ある | **してはいけない。§5 の決裁台帳で裁定を仰ぐ** |

**ラベルの無い記述は本書に存在しない。** もし見つけたら、それは書き漏れなので【未裁定】として扱う。

### 規律 2 — すべての【確定】に出典が付く

`file:line` か、発注者の指示日を必ず添える。**出典の無い断定は書かない。**
出典を出せないことは「原文に記載なし」と書く。「〜のはず」「〜だと思われる」は本書に書かない。

### 規律 3 — 1 語 1 定義（§1）

同じものを別の名前で呼ばない。違うものを同じ名前で呼ばない。
§1 の用語表に無い語を、本書と実装のコメントで使わない。

### 規律 4 — 【未裁定】に実装で答えを出さない

「どちらか決まっていないので、とりあえず動く方で作った」を禁止する。
**過去 2 回の作り直しは、どちらもこれが原因。** 迷ったら §5 に足して止める。

## 0. 目的

> # ユーザーが病気にならないようにすること。

それだけ。

Elith が「こうすれば病気を防げます」と書いてくれる。
**この機能は、それをユーザーに実行してもらうためにある。**

**読ませることが目的ではない。実行してもらうことが目的。**
どれだけ綺麗に読めても、ユーザーが何もしなければ**この機能は失敗**である。

### 0.1 だから、これらは全部「手段」【確定】

| よく目的と取り違えられるもの | 実際 |
|---|---|
| 可読化する | **手段**。読めなければ実行されないから |
| 報告書を届ける | **手段**。届かなければ実行されないから |
| 商品を納品する | **手段**（§0.3） |
| Elith の出力を画面に出す | **手段** |
| フォーマットを変換する | **手段ですらない**。目的とも関係がない |

**実装案の判定基準はこれ 1 つ。**

> **その案は、ユーザーが実際に何かをする確率を上げるか。**

上げないなら、どれだけ綺麗でも目的に寄与していない。

## 4. 確定していること

### 4.1 紙面に出る文はすべて受領物からの逐語【確定】

発注者指示 2026-08-29。要約・言い換え・語順の入れ替え・当社の散文の追加は不可。
**原文の誤字も直さない**（実データの「基準範囲を上上回っており」はそのまま出す）。

**例外は構造ラベルだけ**（カード見出し・表の列見出し・ボタン文言）。
ただし対応する `section_name` や `###` 見出しがあるときは**それを使う**。当社が言い換えた見出しを作らない。

**現在の唯一の例外文** = `report-adapter.ts:51-54` `PILOT_CANCER_FINDING_TEXT`（2 文）。
Elith へ依頼中の文型そのもの。回答後に Elith 出力か `ui.cancer_screening_not_included` へ置き換わる。

### 4.2 章立て・文言・開閉は `app_config` に出す【確定】

コードに埋めない。`report.sections.{order,hidden,labels,collapsed}` /
`ui.cancer_screening_not_included`。既定は全て空＝コード既定。反映は TTL 45 秒。
**未知キー・空白だけの値ではコード既定へ落ちる**（打ち間違いで報告書を白紙にしない）。

### 4.3 受領形式 → 表示モデル → レンダラ の 3 層【確定】

受領形式の世代差はアダプタ 1 枚で吸収する。画面は表示モデルしか知らない。
**§2.2 の実測どおり形式は現に変わっているので、これは理論ではなく必須**。

### 4.4 抽出は fail-safe。ただし黙って空にしない【確定】

拾えなければ何も出さない（誤った要点を出さない）。
**その代わり黙って空になる**ので、admin へ抽出監査を出す。
2026-08-29 に主軸 B が丸ごと白紙になったのはこの failure mode。

### 4.5 画面と印刷は同じレンダラ【確定】

`?print=1` はモード引数であって別実装ではない。章を足したら印刷にも自動で載る。
iOS の「共有 → PDF」は `@media print` を通らないので、**印刷 CSS に依存した設計を採らない**。

### 4.6 モックは実装と機械で突き合わせる【確定】

`docs/elith/mock/*.html` → `sheet_contract_type2.json` → `npm run verify:sheet-contract`。
紙面を変える手順は **モック → 契約再生成 → 実装** の順のみ。契約 JSON を手で書き換えて通すのは禁止。

## 7. なぜ誤読が起きたか（再発防止）

### 7.1 実際に起きたこと

| 回 | 何が起きたか | 直接の原因 |
