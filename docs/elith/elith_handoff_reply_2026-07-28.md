---

## 1. 「2026-07-23 に血液検査結果データが無い」について

**欠損ではなく、仕様どおりの配置**です。血液データ（`BloodTestData`）のみ、他の種別と扱いを変えています。

- 検診・遺伝子・がん・問診・ウェルネス年齢は、**その回の納品日フォルダ**（例 `date/2026_07_23/`）にまとめて配置します。
- **血液のみ、各「採血日」フォルダに配置**します。理由は、血液は**年複数回の時系列を丸ごと納品**する仕様のため、同一日付フォルダに入れるとファイル名が衝突するためです。
- したがって当該ユーザーの血液は、**`2026_07_23/` ではなく、採血日フォルダ**
  `user/{client_id}/date/{採血日}/BloodTestData_date_{採血日}_user_{client_id}.json`
  に格納されています。そちらをご確認ください。
- 補足：合成テストユーザーで血液ソースが割り当てられていない場合は、血液自体が生成されません。

**（本件は現状仕様のまま運用します。）** もし「全種別を1フォルダで参照したい」等のご要望があれば、
「最新血液を納品日フォルダにも併置」または「ユーザー単位のインデックス提供」で対応可能です。ご希望をお知らせください。

---

## 2. 「スキーマの揺れ」について ― 確定JSONスキーマを提供します

ご指摘を受け、**全 format を1つの確定スキーマに固定**しました（添付 `docs/elith/elith_handoff.schema.json`, JSON Schema 2020-12）。
これを契約として、以降の納品はこの構造に準拠します。要点は以下です。

- **共通エンベロープ**（全 format 共通）：`format_id` / `schema_version`("elith-handoff-v0.1") / `client_id` / `diagnostic_id` / `test_date` / `exported_at` / `subject{sex,age}` / `source` / `data` / `raw_markdown`。
- **`data` 直下は format_id で切替**（スキーマ内の `allOf + if/then` で厳密化）：
  - 検査値型（`BloodTestData` / `CancerRiskAssessmentData` / `HealthCheckupData`）… **共通 `measurements[]`**（`name`/`name_detail`/`value`/`value_num`/`unit`/`ref_low`/`ref_high`/`flag`/`note`）。
  - `GeneticTestResultData` … `items[]`。**遺伝子はレポート体系が項目ごとに異なるため、固定キーを課さず柔軟構造**（意図的。`category` はここでのみ保持）。
  - `LifestyleQuestionnaireData` … `answers[]`（設問・回答・ラベル）。
  - `HealthAgeData` … `health_age` / `actual_age` / `computed_date` / `delta` / `model_version`。
  - `Other` … 自由構造（`kind` + `payload`）。
- **日付の考え方（誤解が生じやすい点）**：**フォルダ名の日付＝納品日**、**JSON内 `test_date`＝原本の実施日**で、両者は一致しないことがあります（意図的）。判定は必ず `test_date` をご利用ください。

> 補足：検査値型で以前ばらついていた `value`（数値と単位の混在）・`bbox`/`region`/`category` は、
> 現行仕様で解消済みです（値は数値のみ、単位は `unit`、判定は `flag` に分離／版面・区分は非同梱）。
> もし旧い納品ファイルで揺れを検知された場合は、その具体ファイル名を1点お知らせいただければ、
> 該当ファイルを新スキーマで再生成いたします。

## 3. 「マスキング範囲の定義」について ― 定義書を添付します

添付 `docs/elith/elith_masking_definition.md` に明文化しました。要旨は次のとおりです。

- **マスキング = ①PIIを構造的に非同梱 ＋ ②版面・内部メタの除去**。**検査値そのものは伏字化しません**。
- **非同梱（PII）**：氏名・住所・生年月日・連絡先等。代わりに `subject{sex, age}` のみ（`age`は満年齢、DOBは載せない）。個人特定は **仮名 `client_id`（= `diagnostic_user_id`）** のみ。
- **除去（版面・内部メタ）**：`bbox`/`regions`/`region`、監査列（`No`/`推論値`）、検査値型の `category`（区分）、`raw_markdown` の bbox コメント。
- **保持（対象外）**：検査値・単位・基準値・flag・note、遺伝子の `category`/`items`、血液の判定コード（`assessment` として値に付与）、問診回答。

## 4. 「`LifestyleQuestionnaireData_date_2026_07_23_user_elith-test-002.json` の元データ」について

- **`elith-test-002` は実在人物ではなく、検証用の合成テストID**です（納品セット組立時に採番）。
- **元ファイルの所在は、お渡ししている当該JSONの `assembled_from` フィールドに記録**しています。
  その値（元S3キー）が**元データのディレクトリ**です。新たな書き出しは不要で、そちらを直接ご参照ください。
- 問診データは、スキャンのような**別の原本（画像等）を持ちません**。`data.answers[]` と `raw_markdown` が**元データの全量**です（`assembled_from` の元ファイルも、差分は `client_id` が仮名である点のみ）。
- 恐れ入りますが、**元ファイルの置かれたソース用プレフィックスへ、貴社のS3読み取りアクセスが有効か**をご確認ください。
  権限が無い場合は、当該パスへ読み取り権限を付与（または当該ファイルの開示用コピー配置）で対応いたします。
