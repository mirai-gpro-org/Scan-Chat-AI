# 納品JSON 改善のご報告（Elith 様向け）

いつもお世話になっております。ご指摘（分析に不要な項目・値の冗長・`category` 等）を受け、
納品JSONを**分析に必要な最小構成**へ整理しました。更新版JSONと併せてご確認ください。

## 改善の考え方
- **納品の「形」は当社プログラムで決定論的に確定**（安定・検証可能な契約に）。
- **LLM抽出は「精度」に専念**（列ズレ・隣接行混線の低減）。
- **監査情報（版面・原本等）は当社側の元データに保持**し、納品物には含めません。

## 主な変更点（Before → After）

### 1. 検査値項目 `measurements[]`（がんリスク・検診 共通）
- **不要フィールドを除去**：`region` / `no` / `category` / `name_detail` / `note`（監査用は当社保持）。
- **値の冗長を解消**：`value`("32.7 ↑") と `inferred`("32.7") の二重をやめ、
  **数値は `value_num`（数値型）に一本化**。矢印(↑)等の記号は値に含めません。
  （定性結果は `value` 文字列で保持：例 `"(-)"`）
- **未測定（値なし）項目を納品から除外**（分析対象のみ）。
- `unit` / `ref_low` / `ref_high` / `flag`(H/L) は維持（基準値・単位は数値/標準表記）。

**Before**
```json
{ "region":"左側検査表","no":"5","name":"BMI","name_detail":null,
  "value":"32.7 ↑","inferred":"32.7","unit":"kg/m²",
  "ref_low":"18.5","ref_high":"24.9","flag":"H","note":"-" }
```
**After**
```json
{ "name":"BMI","value_num":32.7,"unit":"kg/m²",
  "ref_low":18.5,"ref_high":24.9,"flag":"H" }
```

### 2. 血液検査 `BloodTestData`
- **`category`（区分1/2/3）を廃止**（項目種別は納品に出しません）。
- **判定コード（区分3：A3 / F2 等）は納品しない**。
- **問診（生活習慣）項目は血液から分離し `LifestyleQuestionnaireData` へ**（血液は検査値のみ）。
- 空値項目を除外。

### 3. 品質（抽出精度・検証）
- LLMスキャンの**列ズレ・隣接行混線を低減**（構造化出力化）。
  - 例）今回の旧データで検知した事象：HDL行の列ズレ、体脂肪率と腹囲の同値（行混線）等。
- **納品前に妥当性チェック**（例：体脂肪率≤100%、単位整合、値と基準値の整合）で異常値を検知・除外。

### 4. 検査票の読取仕様（今回の確定事項）
- **時系列列は「今回」のみ採用**：検査票に「今回／前回／前々回」や受診日付きの複数回分が
  横並びの場合、**"今回"（最新回）の値だけを納品**し、前回・前々回以前は採用しません。
  今回が空欄の項目はその回を空として扱い、過去回の値を繰り上げません（時点を混在させない）。
  **検診・人間ドックに限らず、血液・がん・遺伝子など全検査票で共通**とします。
- **総合判定（A/B/C…）欄は納品対象外**：検査票の「項目別判定」欄（内科診察=A 等の
  ランク文字だけの欄）は測定値ではないため `measurements[]` に含めません。
  個々の検査値の高低は各項目の `flag`(H/L) で表します。
  （※血液型(ABO/Rh)の "A"/"B" 等は定性の検査"値"のため通常どおり納品します）
- **未測定（空白）行は納品しない**（前掲のとおり、分析対象の実測値のみを収録）。

## 監査・トレーサビリティ
- `region` / `no` / 原本Markdown / 出所キー等は**当社側の元データに保持**し、納品物には含めません
  （必要時は当社で追跡可能）。
