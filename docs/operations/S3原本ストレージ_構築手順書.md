# S3 原本ストレージ 構築手順書 (案C′)

検査結果の**原本ファイル (PDF / CSV)** を S3 `ap-northeast-1` に保管するための
インフラ設定手順。アプリ側の実装は完了しており、**この手順を実施して env を
設定した時点で保存先が S3 に切り替わる** (未設定のあいだは Supabase Storage)。

- 実装: `src/lib/originals-storage.ts` / `src/pages/api/admin/lab-results/upload.ts`
- 設計の根拠: `docs/architecture/test_data_storage_and_db_design.md` §6.1-6.3
- 採用の経緯: DB は Supabase (US Central) 据え置き、原本だけ国内へ。署名 URL で
  ブラウザとストレージが直結するため、Vercel (iad1) は配信経路に入らない。

> **この作業には AWS コンソール/CLI の権限が必要です。**
> Gemini/AWS のキーは Vercel 本番 env で一元管理する方針 (CLAUDE.md) のため、
> 開発側では実施できません。Wellfort / UNFIX の AWS 管理者が実施してください。

## 0. 事前に決めること

| 項目 | 推奨値 | 備考 |
|---|---|---|
| バケット名 | `wellfort-diagnosis` | 既存 seed が `s3://wellfort-diagnosis/raw/...` を前提に書かれている |
| リージョン | `ap-northeast-1` | データ主権要件 (`docs/funding_application/要件定義書.md:208`) |
| プレフィックス | `raw/` | env `AWS_S3_ORIGINALS_PREFIX` の既定値 |
| Object Lock モード | **まず GOVERNANCE** → 本番移行時に COMPLIANCE | 下の警告を必ず読むこと |

> ### ⚠ Compliance モードは「削除できない」を文字どおり意味します
> AWS 公式 ([Object Lock overview](https://docs.aws.amazon.com/AmazonS3/latest/userguide/object-lock-overview.html)):
> 「In *compliance* mode, a protected object version can't be overwritten or deleted
> by **any user, including the root user in your AWS account**.」
> 「The only way to delete an object under the compliance mode before its retention
> date expires is to **delete the associated AWS account**.」
>
> **現在はテストフェーズで、架空データの投入と削除を繰り返します。**
> この段階で Compliance / 10 年を掛けると、テストデータを 10 年間削除できません。
> → **テスト中は GOVERNANCE モード**にして、本番運用の開始時に COMPLIANCE へ切り替えてください。
> (GOVERNANCE は `s3:BypassGovernanceRetention` 権限を持つ利用者だけが削除できる)

> ### ⚠ 有効化は取り消せません
> AWS 公式 ([Configuring Object Lock](https://docs.aws.amazon.com/AmazonS3/latest/userguide/object-lock-configure.html)):
> 「After you enable Object Lock on a bucket, you **can't disable Object Lock or
> suspend versioning** for that bucket.」
> また Object Lock 有効バケットは**サーバアクセスログの出力先にできません**。

## 1. バケット作成

Object Lock は**既存バケットにも後から有効化できます** (同公式ドキュメント
「Enable Object Lock on an existing S3 bucket」)。新規作成時に有効化しても構いません。

```bash
# 新規作成 (Object Lock 有効。バージョニングも自動で有効になる)
aws s3api create-bucket \
  --bucket wellfort-diagnosis \
  --region ap-northeast-1 \
  --create-bucket-configuration LocationConstraint=ap-northeast-1 \
  --object-lock-enabled-for-bucket

# パブリックアクセスを全面ブロック (検査結果の原本なので必須)
aws s3api put-public-access-block \
  --bucket wellfort-diagnosis \
  --public-access-block-configuration \
    "BlockPublicAcls=true,IgnorePublicAcls=true,BlockPublicPolicy=true,RestrictPublicBuckets=true"

# 保存時暗号化 (SSE-S3。KMS を使う場合は要件に合わせて変更)
aws s3api put-bucket-encryption \
  --bucket wellfort-diagnosis \
  --server-side-encryption-configuration \
    '{"Rules":[{"ApplyServerSideEncryptionByDefault":{"SSEAlgorithm":"AES256"},"BucketKeyEnabled":true}]}'
```

バージョニングが有効か確認 (Object Lock の前提):

```bash
aws s3api get-bucket-versioning --bucket wellfort-diagnosis
# → { "Status": "Enabled" }
```

## 2. Object Lock の既定保持期間

### テストフェーズ (今)

```bash
aws s3api put-object-lock-configuration \
  --bucket wellfort-diagnosis \
  --object-lock-configuration \
    '{"ObjectLockEnabled":"Enabled","Rule":{"DefaultRetention":{"Mode":"GOVERNANCE","Days":30}}}'
```

### 本番運用開始時 (10 年保管・削除不可)

```bash
aws s3api put-object-lock-configuration \
  --bucket wellfort-diagnosis \
  --object-lock-configuration \
    '{"ObjectLockEnabled":"Enabled","Rule":{"DefaultRetention":{"Mode":"COMPLIANCE","Years":10}}}'
```

`docs/architecture/test_data_storage_and_db_design.md` §6.1「原本保管 10 年・削除不可」を
運用ルールではなく**技術で担保**するのがこの設定の目的です。

## 3. ライフサイクル (コスト最適化)

原本は基本的に読み出しません。段階的に安いクラスへ移します。

```bash
aws s3api put-bucket-lifecycle-configuration \
  --bucket wellfort-diagnosis \
  --lifecycle-configuration '{
    "Rules": [{
      "ID": "raw-originals-tiering",
      "Filter": { "Prefix": "raw/" },
      "Status": "Enabled",
      "Transitions": [
        { "Days": 30,  "StorageClass": "STANDARD_IA" },
        { "Days": 90,  "StorageClass": "GLACIER_IR" }
      ],
      "NoncurrentVersionTransitions": [
        { "NoncurrentDays": 30, "StorageClass": "STANDARD_IA" }
      ]
    }]
  }'
```

料金 (AWS Price List API・2026-08-20 取得・`ap-northeast-1`):

| クラス | 保管 | 取り出し |
|---|---|---|
| S3 Standard | $0.0250 /GB-月 | — |
| S3 Standard-IA | $0.0138 /GB-月 | $0.01 /GB |
| S3 Glacier Instant Retrieval | $0.0050 /GB-月 | $0.03 /GB |

> **Expiration ルールは設定しないでください。** 10 年保管が要件です。
> Object Lock 保護中のオブジェクトはライフサイクルでも削除されません。

## 4. IAM (アプリ用の最小権限)

アプリが必要とするのは **PutObject / GetObject** だけです。削除権限は与えません。

```json
{
  "Version": "2012-10-17",
  "Statement": [
    {
      "Sid": "AppPutGetOriginals",
      "Effect": "Allow",
      "Action": ["s3:PutObject", "s3:GetObject"],
      "Resource": "arn:aws:s3:::wellfort-diagnosis/raw/*"
    },
    {
      "Sid": "AppListForDebug",
      "Effect": "Allow",
      "Action": ["s3:ListBucket"],
      "Resource": "arn:aws:s3:::wellfort-diagnosis",
      "Condition": { "StringLike": { "s3:prefix": ["raw/*"] } }
    }
  ]
}
```

`s3:DeleteObject` と `s3:BypassGovernanceRetention` は**アプリに付与しません**
(誤削除を構造的に防ぐため。運用上の削除は管理者の別ロールで行う)。

## 5. Vercel 環境変数

**既存の `AWS_S3_BUCKET` (Elith 連携用 `wellfort-ai-input`) は変更しないでください。**
原本用は別変数です。

| 変数 | 値 | 必須 |
|---|---|---|
| `AWS_REGION` | `ap-northeast-1` | ○ (既存と共用) |
| `AWS_S3_ORIGINALS_BUCKET` | `wellfort-diagnosis` | ○ **これが切替スイッチ** |
| `AWS_S3_ORIGINALS_PREFIX` | `raw/` | 任意 (既定 `raw/`) |
| `AWS_ACCESS_KEY_ID` / `AWS_SECRET_ACCESS_KEY` | 上記 IAM のキー | 任意 (既定のチェーンで解決できるなら不要) |

`AWS_S3_ORIGINALS_BUCKET` が未設定のあいだは Supabase Storage に保存されます
(`src/lib/originals-storage.ts` `getOriginalsS3Config()`)。**設定漏れで壊れることはありません。**

設定後は再デプロイが必要です (env はビルド時に読まれるため)。

## 6. 動作確認

1. `/admin/lab-results/upload` から PDF を 1 件アップロードする。
2. API 応答の `uploaded[].backend` が `"s3"` になっていること
   (`"supabase"` のままなら env が効いていない)。
3. DB を確認する:

```sql
select file_kind, storage_url, length(sha256) as sha_len, size_bytes
from diagnosis.test_artifact_files
order by created_at desc limit 5;
```

- `storage_url` が `s3://wellfort-diagnosis/raw/...` になっていること
- `sha_len` が **64** であること (従来は空文字だった。§6.1 の改竄検知要件)

4. `/result/<artifact_id>` を開き、原本 PDF が表示されること
   (署名 URL は既定 5 分で失効します)。

## 7. 既存データの移送

現在 Supabase Storage の `lab-results` バケットに入っている原本を S3 へ移します。
**読み出しは `storage_url` の形 (`s3://` かどうか) で自動的に振り分かる**ため、
移送は急ぎません。少量のうちに実施するのが望ましい、という位置づけです。

移送時は次の 2 つをセットで行ってください。

1. オブジェクトを S3 の同じキーへコピー
2. `diagnosis.test_artifact_files.storage_url` を `s3://<bucket>/raw/<key>` へ更新
