## 0. 本書の目的と全体像

本補助事業 (健康データ統合・AI 個別健康アドバイス生成システム) では、以下の処理で Google Gemini API を利用します。

| 利用場面 | モデル | API 種別 |
|---|---|---|
| 検査票 AI スキャン (OCR + 構造化抽出) | `gemini-2.5-flash` | REST (generateContent) |
| AI 問診の音声対話 | `gemini-3.1-flash-live-preview` | Live API (WebSocket) |
| AI ヘルスコーチ Q&A | `gemini-2.5-flash` | REST (generateContent) |

これらの API はすべて **Generative Language API** (Google AI Studio が窓口) を経由します。**API キーは Wellfort 法人アカウント配下の GCP プロジェクトで発行** し、料金 (従量課金) は Wellfort の請求アカウントに請求される構成です。発行されたキーは UNFIX 社が本番環境 (Vercel) の環境変数に設定し、サーバ側からのみアクセスされる運用となります。

### 0.1 前提

- ✅ Wellfort 法人 Google アカウントへログイン可能
- ✅ **GCP プロジェクト作成済** (プロジェクト ID をお手元にご準備ください)
- ✅ **請求アカウントとの紐付け完了済**

### 0.2 全体フロー (本書がカバーする範囲)

```
[完了済]  GCP プロジェクト作成 + 請求アカウント紐付け
   ↓
[手順 1]  Generative Language API の有効化
   ↓

   ↓

   ↓
[手順 4]  UNFIX 担当者への安全な引渡し
   ↓
[手順 5]  予算アラートの設定 (推奨)
```

## 1. 手順 1 — Generative Language API の有効化

API キーを発行する前に、対象 API を有効化する必要があります。

1. Google Cloud Console を開く: **https://console.cloud.google.com/apis/library**
2. 画面上部の **プロジェクトセレクタ** が、本補助事業用に作成いただいたプロジェクトになっていることを確認してください。
   - もし別のプロジェクトが選択されている場合は、セレクタをクリックして対象プロジェクトに切替えてください。
3. 検索バーに「**Generative Language API**」と入力します。
4. 検索結果から「**Generative Language API**」を選択。
5. 「**有効にする**」ボタンをクリック。
6. 「API はこのプロジェクトで有効です」と表示されれば完了です。

> **💡 補足**: 検索結果に類似名 (Vertex AI 等) が出ますが、本補助事業では **Generative Language API** を選んでください。

---

## 2. 手順 2 — API キーの発行

1. ブラウザで Google AI Studio を開く: **https://aistudio.google.com/apikey**
   - Wellfort 法人アカウントでログイン中であることを画面右上のアイコンで確認してください。
2. 「**Create API key**」または「**API キーを作成**」をクリック。
3. プロジェクト選択ダイアログで、**手順 1 で API を有効化したプロジェクト** を選択します。
4. 生成された API キー文字列 (例: `AIzaSy……` で始まる 39 文字) が表示されます。
5. **画面の「Copy」ボタンで API キー全文をコピー** してください。

> **⚠️ 重要**: API キーは画面に何度でも表示できますが、**一度漏洩すると不正利用に直結する** ため、コピー後は直ちに後述 §4 の方法で安全に保管・引渡してください。

> **💡 補足**: AI Studio の画面で確認できる API キー一覧から、後で再表示・名前変更・削除・再生成が可能です。

## 3. 手順 3 — API キーの制限設定 (強く推奨)

発行直後の API キーは「何にでも使える」状態のため、漏洩リスクを下げるため **利用範囲を Generative Language API に限定** することを強く推奨します。

1. Google Cloud Console: **https://console.cloud.google.com/apis/credentials**
2. プロジェクトが正しく選択されていることを確認。
3. 「API キー」一覧から、先ほど作成したキーをクリック。
4. **キー名** を分かりやすい名称に変更:
   - 推奨: `Wellfort-Scan-Chat-AI-Production-Key`
5. **「API の制限」セクション**:
   - 「**キーを制限**」を選択
   - リストから「**Generative Language API**」のみにチェック
   - 「保存」をクリック
6. **「アプリケーションの制限」セクション** は **「なし」のまま** で構いません。
   - Vercel のサーバから呼び出すため、固定 IP 制限は実用的でない (Vercel の egress IP は変動するため)
   - より厳格にしたい場合は別途 UNFIX 担当にご相談ください

## 4. 手順 4 — UNFIX 担当者への安全な引渡し

API キーは漏洩すると **不正利用 (請求書ショック)** に直結します。以下の方法で安全に引渡してください。

### 4.1 推奨される引渡し方法

| 方法 | 安全度 | 補足 |
|---|:---:|---|
| **Google Workspace の共有ドライブ** (アクセス権限を UNFIX 担当者のメールに限定) | ★★★ | 最推奨。閲覧履歴が残る・アクセス権変更で即時失効可能 |
| **1Password / Bitwarden 等の暗号化共有** | ★★★ | パスワード共有機能を利用 |
| **PGP 暗号化メール** | ★★★ | 受信側の公開鍵が必要 |
| **Slack DM 等のチャット直接送信** | ★★ | 送信後すぐに削除すること |

### 4.2 絶対に避けてください

- ❌ メール本文への平文での貼付 (送信履歴に残る)
- ❌ チャット公開チャンネル / メーリングリストへの貼付
- ❌ Word / Excel / PowerPoint ファイルへの記載 + メール添付
- ❌ スクリーンショットでの送信 (画像ファイル管理が雑になる)
- ❌ クラウドストレージへの「リンクを知っている全員」共有

### 4.3 引渡し後の運用

1. UNFIX 担当者は受領した API キーを **Vercel 本番環境の環境変数 `GEMINI_API_KEY`** に設定します。
2. Wellfort 側でも API キー本体を **法人パスワードマネージャ** に保管してください (緊急時の再発行・キーローテーションのため)。
3. **3 か月に 1 回程度** 、API キーのローテーション (再発行 + 環境変数更新) を推奨します。

## 5. 手順 5 — 予算アラートの設定 (強く推奨)

予期しない請求を防ぐため、**予算アラート** を設定してください。

1. Google Cloud Console > **「請求」 > 「予算とアラート」**
   - URL: **https://console.cloud.google.com/billing/budgets**
2. 「**予算を作成**」をクリック。
3. 予算名: `Wellfort Gemini API 月次予算`
4. 対象: 本補助事業用プロジェクトを指定。
5. 予算額: **30,000 円 / 月** (推奨初期値・必要に応じて調整)
6. アラートのしきい値: **50% / 90% / 100%** で通知する設定を有効化。
7. 通知先メールアドレス: **Wellfort 担当者 + UNFIX 担当者の双方** を登録。

## 7. トラブルシューティング

| 症状 | 原因 | 対処 |
|---|---|---|
| 「API key not valid」エラー | API キーが間違っている / Generative Language API が無効 | 手順 1 で API を有効化、手順 2 でキーを再発行 |
| 「Quota exceeded」エラー | 無料枠を超えたが請求アカウント未紐付け | 請求アカウントの紐付けを再確認 (本書冒頭の前提) |
| 「Permission denied」 | アカウントに Cloud 管理権限が無い | Workspace 管理者に「Project Owner / Billing Administrator」権限の付与を依頼 |
| 想定外の高額請求 | API キー漏洩の可能性 | 即座にキーを削除・再発行 (手順 2)、Cloud Logging で異常アクセスを確認、Wellfort 情報セキュリティ責任者に報告 |
| プロジェクトセレクタに対象プロジェクトが出ない | アカウントが間違っている (個人アカウントでログイン中) | 画面右上のプロフィールアイコンから法人アカウントに切替え |

## 8. 補足 — Vertex AI を使う場合 (将来検討事項)

本補助事業ではまず Generative Language API (AI Studio 経由) で開始しますが、将来的に以下のような要件が出てきた場合は **Vertex AI** への移行を検討してください。

| 検討すべき要件 | Vertex AI のメリット |
|---|---|
| PII を含むデータを送信するため、**Google のモデル学習からの除外** を契約レベルで保証したい | Vertex AI は Customer Data Processing Terms で学習除外を明確化 |
| **東京リージョン (asia-northeast1) 内での処理保証** が必要 | Vertex AI ではリージョン指定が明示的にサポート |
| **HIPAA / ISO 27018 / SOC 2** 等の法令・標準準拠の契約書類が必要 | Vertex AI は Google Cloud BAA の対象 |

移行時の手順は別途 UNFIX 担当者にご相談ください。アプリケーション側の改修は半日〜1 日程度で可能な見込みです。
