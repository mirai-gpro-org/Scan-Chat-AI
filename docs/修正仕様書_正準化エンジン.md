## 1. 現状（出典付き）

- 名称決定は `pickDeliveryName(section, detail)`（`elith-export.ts:364-378`）＝ヒューリスティック（血圧の最高/最低正規化、詳細が汎用語ならセクション名、位置語は結合）。**マスタ照合ではない**。
- `toMeasurements`（`elith-export.ts:379-416`）が `pickDeliveryName` を呼び measurement を生成（:402）。
- `sanitizeMeasurementsForDelivery`（`elith-export.ts:320-347`）が lean 化・未測定除外・総合判定除外・妥当性ガード（S4/S5 相当）。
- **単位の標準化・換算、名寄せの網羅、移植カバレッジ照合は無い**。

## 2. 変更内容

### 2.1 新規ファイル `src/lib/canonicalize.ts`

```ts
import { STANDARD_MASTER, findByAlias, type StandardItem } from './standard-master';

export interface CanonicalizeResult {
  delivery: Record<string, unknown>[]; // 正準化後の納品 measurement（S4後・非空のみ）
  mapped:   { from: string; to: string; unit_from: string|null; unit_to: string|null }[]; // S2 監査
  unmapped: { name: string|null; value: unknown }[]; // S3 未写像（surplus 候補・silent drop しない）
  deficient: string[]; // S3 必須マスタにあるが値が無い（≒未実施 or 実落ち）
}

/** S1〜S3。読取済(sanitize前 or 後)の measurements をマスタへ写像する。決定論・保守的。 */
export function canonicalize(
  measurements: Record<string, unknown>[],
  opts?: { master?: StandardItem[] },
): CanonicalizeResult;
```

### 2.2 処理（S1〜S4 の対応）

- **S1**：`master`（既定 `STANDARD_MASTER`）から `canonical_name`→スロットの索引を用意。
- **S2 写像（保守的）**：各 measurement の `name`（＝`pickDeliveryName` 出力）と `name_detail` の**両方**を `findByAlias` で照合し、**ヒットした方**を `canonical_name` に採用（section/detail のどちらが分析名かを推測しない＝基本設定書 §3 の方針）。
  - **単位正準化**：`unit_aliases` で標準単位へ寄せ、`unit_convert` があり値が数値なら換算（例 g/L→mg/dL）。換算した場合は `mapped` に記録。
  - **高信頼のみ**：完全一致 or 登録同義語のみ採用。曖昧（複数ヒット/部分一致のみ）は**写像しない**。
- **S2 非ヒット時（保守的 fallback）**：正準化せず**元の name のまま通す**（従来 `pickDeliveryName` 出力を維持）＋`unmapped` に記録。**捨てない・別項目に当てない**（漏れゼロ・捏造ゼロ）。
- **S3 カバレッジ**：`unmapped`＝マスタ外（surplus 候補）、`deficient`＝マスタにあるが値が来なかった標準項目。どちらも**削除でなく記録**（silent drop しない）。
- **S4 空スロット削除**：値が無いスロットは納品に載せない（＝既存 `sanitizeMeasurementsForDelivery` の未測定除外に一致。二重に消さない）。

### 2.3 `pickDeliveryName` の扱い

- **置換ではなく前段に残す**：`toMeasurements` は従来どおり `pickDeliveryName` で暫定 name を作り、`canonicalize()` が**その上でマスタ照合して正準名へ寄せる**（非ヒットは暫定 name のまま）。これにより既存 numeric 経路を壊さず、正準化を後段の純粋関数として足せる。
- 将来、マスタが完全化したら `pickDeliveryName` の当て推量を段階的に縮小（基本設定書 §3.6.2 の方針）。

### 2.4 結線（全書き出し経路・env gate）

- 呼び出し位置：`sanitizeMeasurementsForDelivery` の **直後**（sanitize で lean/未測定除外した後の `kept` を `canonicalize` に通す）。
- 対象経路（三経路すべて・二重管理しない）：
  - `buildElithScanBundle`（`elith-export.ts:903` の `sanitizeMeasurementsForDelivery(...).kept`）
  - `hc-merge`（`elith-hc-merge.ts:162`）
  - `assemble`（`elith-assemble.ts:279`）
- **env gate（新規提案）`SCAN_CANONICALIZE`（既定 off）**：off の間は現行と完全同一挙動。🎯確認後に on（回帰したら即 off でロールバック）。実装は `scanOutputFormat`/`boundaryRecheckEnabled`（`elith-export.ts:65/73`）と同型の判定関数を追加。

### 2.5 ①VQA との順序（層を混ぜない）

- **VQA（①・`boundaryRecheck` `elith-export.ts:579`）で今回値を確定した後に**②`canonicalize` を通す。3期間リークで過去値が今回に残ったまま②に入ると、正しいスロットに誤値が穴埋めされ発見困難な False-Value になるため（基本設定書 §3.6.1「直交」）。
- ②は**読取値に一切触れない**（name/unit の写像とカバレッジ記録のみ。値の充填・削除は S4 の空判定のみ）。

## 3. 受入基準（🎯）

- **numeric 全一致を維持**（正準化 on/off で numeric 結果が不変）。最重要の非回帰条件。
- 名寄せにより**偽 Missing が減る**（`痛風→尿酸`、`白血球→白血球数` 等）。
- **False-Value = 0**（誤マップを作らない）。危険同義語テスト（`総蛋白`→`尿蛋白` に当てない）green。
- `mapped/unmapped/deficient` が監査に出る（`修正仕様書_検証と確定運用.md`）。

## 4. リスク・ロールバック

- 誤マップ＝捏造 → 保守的（高信頼のみ）＋deny 区別＋`unmapped` 記録。
- numeric 回帰 → ②は後段・読取不変。`SCAN_CANONICALIZE=off` で即ロールバック。
- 単位換算の誤り → `unit_convert` は明示登録のみ。未登録単位は換算せず標準単位名だけ寄せる（値は不変）。
