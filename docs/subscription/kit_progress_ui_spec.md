# 検査キット進捗 UI 進化仕様（サブスク駆動・ユーザー向け）

| 項目 | 内容 |
|---|---|
| 目的 | ダッシュボードの **📦検査キット進捗** を、サブスク契約を起点に **①いつ何のキットが届くか ②受取/返送の自己申告 ③AI問診の促し・自動完了表示** が直感的に分かるUIへ進化させる。 |
| 対象 | Scan-Chat-AI アプリ `src/components/dashboard/KitProgressCard.astro`（`src/pages/dashboard.astro` から利用）。データ層 `src/lib/dashboard-queries.ts`。 |
| 版 | 2026-08-07（Draft・UIイメージ案 同梱） |
| 準拠 | `docs/subscription/kit_lifecycle_and_handoff_management_spec.md`（§2 出荷スケジュール・§3 ライフサイクル/AI問診促し・§6 データモデル）／`docs/lab/kit_progress_management.md`（ライフサイクル実装）／`docs/lab/questionnaire_to_lab_csv_spec.md`（問診が要る検査） |

---

## 1. 現状と課題

**現状**（`KitProgressCard.astro`）:
- **進行中キット**（`lab_completed_at` 未設定・上位2件）だけを表示。6ステップのステッパー（`出荷準備→発送済→お受取→返送→検査会社受領→検査完了`・`shipmentLabel()`）。
- 自己申告ボタン「📦 受け取りました」「💉 返送しました」→ `POST /api/kit/{id}/self-report`。
- `nextTestAt`（次回検査予定日）を1行表示。

**課題（本仕様で解決）**:
1. **「いつ・何のキットが届くか」の予定が見えない**（進行中しか出ず、サブスクの年間スケジュールが不可視）。
2. **AI問診への導線・状態が進捗カードに無い**（問診は別カード。検体返送前の促し・完了の可視化が繋がっていない）。
3. どのアクションを次にすべきか（受取/返送/問診）が**一目で分からない**。

---

## 2. 画面構成（3ゾーン）

> 1枚のカード内を縦に3ゾーン。**上=予定／中=進行中の行動／下=AI問診**。各回（発送回）を軸に束ねる。

### ゾーンA：これから届く検査キット（予定タイムライン）
- サブスクの**出荷スケジュール**（`kit_shipment_schedule`＝契約×回×キット×予定日）を**時系列**で表示。
- 1回分＝1ブロック：**予定日**＋その回の**キット絵文字＋名称**（例 `8/11 初回：🧬遺伝子 🎗️がん 🩸血液`）。
- 直近の回を先頭・強調。以降はグレーで数回先まで。**遺伝子は初回のみ**等のルールを反映（`spec §1/§6.1`）。
- 状態バッジ：`発送準備中／発送済`。発送済になったらゾーンBへ“昇格”。

### ゾーンB：進行中の検査キット（行動）
- 現行の6ステップステッパーを踏襲・改良（現在地を明確化）。**次にやること**をカード最上位のCTAに:
  - 発送済で未受取 → **「📦 受け取りました」**（`received`）。
  - 受取済で未返送 → **「💉 返送しました」**（`returned`）。返送前に**ゾーンCの問診が未完了なら注意表示**（ブロックはしない）。
- 追跡番号（`tracking_no`/`carrier_tracking_url`）はリンク表示（現行踏襲）。
- キットが複数同送（例 幹部初回=3キット）なら**キット別に行**を出す（各キットの状態は独立）。

### ゾーンC：AI問診（促し・自動完了・リセット）
- **問診が必要な検査**（血液 等・`questionnaire_to_lab_csv_spec`）が**その回に含まれるときだけ**表示。
- 状態3種：
  1. **未完了（促し）**：`⚠ AI問診をお願いします` ＋ **「AI問診を始める」CTA**。補足「毎日お知らせします／7日過ぎると担当者に連絡が入ります」（`spec §3.1`）。
  2. **完了**：`✅ AI問診 完了（YYYY/MM/DD）`。CTAは畳む（静かにする）。
  3. **不要**：その回に問診要検査が無ければ非表示。
- **自動完了表示**：ユーザーが問診を完了したら、**リロード不要で**カードが「完了」へ切替（§5 ポーリング/リアルタイム）。
- **リセット**：`✅完了` は、**次の回の検査キットが発送されたタイミング**で新しい回の未完了状態へ戻る（＝回ごとに1問診サイクル。ユーザー指定挙動）。

## 3. データソース

| ゾーン | ソース | 備考 |
|---|---|---|
| A 予定 | `kit_shipment_schedule`（`spec §6.2`。契約→`plan_composition_id`→明細を展開） | 未実装なら暫定で `subscriptions.next_test_at`＋プラン構成から算出 |
| B 進行中 | `kit_shipments`（現行）＋ `kit_lifecycle`（`spec §6.2`） | `shipmentLabel()` を流用 |
| C 問診 | **回×問診完了フラグ**（`lab_handoff` もしくは `interview_status`。`spec §4.1/§6.2`） | 完了信号は既存の問診完了（`interview-export` `completedAt`／`session-store` 進捗100%）を**回に紐付けて**保存 |

- 問診完了の**回への紐付け**が現状データに無い → **`lab_handoff`（回×問診CSV送付/完了）に `interview_completed_at` を持たせる**（実装要件）。

## 4. 状態 → UI マッピング

**6ステップ（ゾーンB）**：`出荷準備(1)→発送済(2)→お受取(3)→返送(4)→検査会社受領(5)→検査完了(6)`（`shipmentLabel()` の step をそのまま利用）。

| 状態 | 主導線（CTA） | ゾーンCの扱い |
|---|---|---|
| 出荷準備 | （ゾーンAに予定表示） | 非表示 |
| 発送済・未受取 | 📦 受け取りました | 問診要なら**促し開始** |
| 受取済・未返送 | 💉 返送しました（前に問診未完了なら注意） | 促し継続（毎日／7日で管理者通知） |
| 返送済〜検査完了 | 進捗表示のみ | 完了なら✅、未完なら促し継続 |

## 5. AI問診 促し・完了・リセットのロジック（`spec §3.1` 準拠）

- **対象回**：その回に**問診要検査**（血液 等）が含まれる場合のみ発火。
- **開始トリガ**：その回のキットが**発送済**（＝検体採取/返送の導線が出る時点）。
- **催促**：未完了の間、**Webアプリ通知で毎日**促す。**ハードブロックしない**（返送は止めない）。
- **エスカレーション**：**7日超で未完了なら Wellfort 管理者へワーニング**（管理ダッシュボードのアラート。UI側は「担当者に連絡が入る」旨を表示）。
- **完了**：問診完了で催促停止 → ゾーンCを **✅完了** に（**自動反映**：`dashboard` を軽量ポーリング〔例 15s〕、または Supabase Realtime で `lab_handoff.interview_completed_at` を購読）。
- **リセット**：**次の回のキットが発送された時**、新しい回の問診状態＝未完了で促しを再開（前回の✅はクリア）。

```
発送(問診要回) ─▶ [未完了:毎日催促] ──(7日超)──▶ 管理者ワーニング
      │                     │
      │                     └──(問診完了)──▶ ✅完了(自動表示・催促停止)
      └──(次の回が発送)──▶ 新サイクル(未完了へリセット)
```

## 6. アクション / API

- 受取/返送：**既存** `POST /api/kit/{shipmentId}/self-report`（`action: received|returned`）を踏襲。
- 問診導線：既存「AI問診を始める」動線（`dashboard.astro`）へリンク。
- 完了状態取得：**新規（軽量）** `GET /api/kit/interview-status?round=…`（または dashboard データに `interview_completed_at` を含める）。ポーリング/Realtimeで自動反映。
- すべて `diagnosticUserId` スコープ（PII非混在・`customer`/`diagnosis` 分離は現行方針）。

## 7. 空・エッジ状態 / レスポンシブ / アクセシビリティ

- **予定なし**：「進行中のキットはありません／次回検査: …」（現行の空表示を踏襲）。
- **複数同送**：ゾーンBはキット別行。ゾーンCは回単位（1問診サイクル）。
- **解約/停止**：以降のゾーンA予定は非表示（`gmo_subscription_billing_spec` の契約状態連動・`spec §2.3-3`）。
- **モバイル優先**：カード幅 100%・タップ領域大きめ・ステッパーは横並び6分割を維持。
- **A11y**：ボタンに `aria-label`、状態はテキスト併記（色のみに依存しない）。ダーク/ライト両対応（現行 Tailwind クラス踏襲）。

## 8. 実装メモ（段階導入）

1. **ゾーンA（予定）を追加**：まず `subscriptions`＋プラン構成から算出（`kit_shipment_schedule` 未実装でも動く暫定）。
2. **ゾーンC（問診）を結線**：`lab_handoff.interview_completed_at` を追加し、回に紐付け。自動反映はポーリングから開始（Realtimeは後段）。
3. 催促（毎日通知）・7日ワーニングは `spec §3.1` のオーケストレーション側と連動（UIは状態表示に徹する）。
4. `KitProgressCard.astro` を3ゾーン構成へリファクタ（ゾーンB＝現行流用）。**既存の self-report・ステッパーは互換維持**。
