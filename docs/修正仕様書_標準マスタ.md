## 1. 現状（出典付き）

- `checkNecessity` は `requiredItemsMaster?: string[]`（`elith-necessity-check.ts:42`）を受けるが、**供給はリクエストbody依存**（`elith-scan.ts:122-125` が `body.requiredItems` を渡すだけ）で、リポジトリに保存された正準マスタが**存在しない**。
- `hc-merge.ts:191` は `checkNecessity(jsonObj)`（マスタ無し＝構造チェックのみ）。
- 名称決定は `pickDeliveryName`（`elith-export.ts:364-378`）のヒューリスティックのみ。**単位の標準化・換算は無い**。

→ **標準マスタ（データ）が無いことが②正準化の唯一の欠落ピース**。

## 2. 変更内容

### 2.1 新規ファイル `src/lib/standard-master.ts`（TypeScript・追加依存なし）

配置理由：`scripts/*.mjs` は追加依存なし方針だが、マスタは型安全に扱いたく、サーバ/バッチ両方から import するため `src/lib/` に TS モジュールで置く。

```ts
export interface StandardItem {
  canonical_name: string;      // 標準項目名（Elith 納品 name）。例: '尿酸'
  synonyms: string[];          // 表記ゆれ・section/detail 候補。例: ['痛風','ＵＡ','尿酸値']
  unit: string | null;         // 標準単位。例: 'mg/dL'
  unit_aliases?: string[];     // 単位ゆれ。例: ['mg/dl','mg／dl']
  unit_convert?: { from: string; factor: number }[]; // 換算（例 g/L→mg/dL）。無ければ換算しない
  ref_low?: string | null;     // 参考（マスタ由来。画像優先・空補完用ではない）
  ref_high?: string | null;
  qualitative?: boolean;       // 定性項目か（尿定性・便潜血・K-W 等）
  category?: string;           // 分類（血液一般/脂質/肝機能…）監査・並び用
  source_std?: 'KMAT' | '特定健診' | 'both' | 'starter'; // 由来（トレーサビリティ）
}
export const STANDARD_MASTER: StandardItem[];
export function masterItemNames(): string[]; // checkNecessity 用 allowlist
export function findByAlias(name: string): StandardItem | null; // 正準化エンジン用
```

### 2.2 starter マスタの収録範囲（捏造ゼロ・R3）

- **代表ゴールデン検体（`scan_golden_healthcheckup_20250123.md`）に実在する標準項目のみ**を収録。存在しない標準名を作らない。
- 実名例（すべてゴールデンに実在）：`最高血圧`/`最低血圧`、`白血球数`、`赤血球数`、`血色素量`、`空腹時中性脂肪`、`総コレステロール`、`HDLコレステロール`、`LDLコレステロール`、`空腹時血糖`、`AST(GOT)`、`ALT(GPT)`、`γ-GTP`、`ALP`、`クレアチニン`、`eGFR`、`尿酸`、`尿蛋白`、`尿潜血`、`尿糖`、`免疫便潜血反応 1日目/2日目`、`K-W分類右/左`、`裸眼視力右/左`、`眼圧右/左`、身体計測（身長/体重/BMI/腹囲/標準体重）等。
- 各項目の `synonyms` は**実測の表記ゆれ**（`最高血圧↔最大血圧↔収縮期血圧`、`白血球数↔白血球`、`裸眼視力右↔裸眼右`。出典: `scan_golden_healthcheckup_20250123.md` §名称ゆれ）を収録。
- **危険な同義語は入れない**（例: `蛋白`＝尿蛋白 と 総蛋白 を同一視しない。`潜血`＝尿潜血 と 便潜血 を区別）。誤マップ＝捏造の温床になるため。

### 2.3 供給先（このマスタを使う場所）

1. `checkNecessity` の `requiredItemsMaster` 既定値（`修正仕様書_検証と確定運用.md`）。
2. 正準化エンジン `canonicalize()` の写像テーブル（`修正仕様書_正準化エンジン.md`）。

## 3. 完全マスタへの差替（P5）

- KMAT ver5.0（約2000項目）/ 特定健診法定項目の一次資料を受領したら、starter を権威データへ置換（`source_std` で由来を管理）。入手先は推進機構/HASTOS or クライアント/Elith（基本設定書 §2.4.1 注記・R3）。
- 差替時も `StandardItem` インターフェースは不変に保つ（正準化エンジンを触らずデータ差替のみで拡張）。

## 4. 受入基準

- `masterItemNames()` がゴールデンの全「今回実施項目」を包含（照合器の名寄せ後 Missing がマスタ起因で増えない）。
- `findByAlias('痛風')`→`尿酸`、`findByAlias('白血球')`→`白血球数` 等、実測ゆれが解決。
- 危険同義語テスト：`findByAlias('総蛋白')` が `尿蛋白` に**当たらない**こと。
