## 1. ゲート G1：未実施ブロックの定性(-)充填を抑制（尿定性 / 便潜血）

**問題**：今回=未実施の尿ディップ/検便で、salvage と VQA が基準列/前回列の(-)を today に充填 → 捏造。

**決定論シグナル（列来歴の代理・高信頼）**
- **尿ディップの実施アンカー = 比重(numeric) と pH(numeric)**。真の尿検査なら比重(1.0xx)・pHが**必ず native 数値**で入る（数値は(-)吸い上げバグの対象外）。
  → **同一検査票で 比重・pH がともに今回=空なら「尿ディップ未実施」と判定**し、尿定性(尿蛋白/尿潜血/尿糖/ケトン体/ウロビリノーゲン)の **salvage 移送・VQA fill を抑止**（left_unresolved に留める）。
- **便潜血**：数値アンカーが無い。**1日目・2日目がともに native 結果(-)を持たない（＝空/ref由来のみ）なら未実施**とみなし、VQA fill を抑止。CLAUDE.md 確定挙動「埋めると捏造になるので空のまま(捏造ゼロ)」に一致。

**アクション**：該当ブロックが「未実施」判定のとき、その定性項目は **value を空のまま**（salvage no-op / VQA=left_unresolved）。**numeric・実施済ブロックには一切触れない**。

**fail-safe / 回帰防止**
- 実施ブロック（比重 or pH が native にある）では**従来どおり救済が働く**＝既存 🎯 回帰ゼロ。
- 「実施で全項目(-)だが比重/pHも吸われた」極端 run では未実施と誤判定し得るが、**その場合の充填は捏造リスク側なので空が安全**（CLAUDE.md 方針）。

**実装箇所**：`sanitizeMeasurementsForDelivery` はリスト全体を持つので、
1. 冒頭で**ブロック実施フラグ**を算出（尿=比重/pHの native 有無、便=便潜血の native(-)有無）。
2. `salvageQualitativeResult` を**リスト文脈付き**に変更（未実施ブロックの対象名は移送しない）。
3. `boundaryRecheck` に**未実施フラグ**を渡し、missing_detection の fill をスキップ（`elith-export.ts:797-799`）。

**env**：`SCAN_FABGATE_UNPERFORMED`（off=従来どおり）。**監査**：抑止した項目を VqaAuditEntry / anomalies に `reason:'unperformed_block'` で可視化（納品 data には出さない）。

## 2. ゲート G2：基準値/閾値の value 化をドロップ（基準吸い上げ）

**問題**：腹囲=84.9（基準「84.9以下」）のように、**value が自分の基準閾値と一致**＝結果でなく基準を読んでいる。

**決定論シグナル（高信頼）**
- `value_num` が、同じ行の **ref から一意に定まる片側閾値**（`ref_high`/`ref_low`、または value/ref 文字列中の `X以下|X以上|X未満|Xを超える|≦X|≧X`）の **数値と厳密一致**するとき、その value は基準の写し。
- **片側（以下/以上等）に限定**。両側レンジ(`A〜B`)は value=A/B が実測でもあり得るため対象外（それは G3 で別扱い）。

**アクション**：value/value_num をドロップ（未測定＝納品しない）。**監査 `reason:'ref_bleed'`**。

**fail-safe**：「value が印字された片側閾値と数値まで一致」は実測が偶然一致する確率が低く、かつ**基準そのものを結果扱いする方が有害**。厳密一致のみ・片側のみで誤ドロップを最小化。

**実装箇所**：`sanitizeMeasurementsForDelivery` の妥当性ガード段（`measurementAnomalyReason` 近傍・`:428` 付近）に判定を追加。**env**：`SCAN_FABGATE_REFBLEED`。

## 3. ゲート G3：参考資料/基準値表の行を除外（B3 由来）

**問題**：B3（遊離テストステロン基準値表・患者データでない）から「男性 7.6〜23.8」「女性 0.4〜2.3」等を項目化＝余剰/捏造。

**決定論シグナル（高信頼・2条件のいずれか）**
- **(A) value がレンジ/基準表記のみ**：`^\s*\d+(\.\d+)?\s*[〜~-－]\s*\d+(\.\d+)?\s*$` ／ `^\s*\d+(\.\d+)?(以下|以上|未満|超)\s*$` ／ `^\s*未設定\s*$` を value 全体が満たす → **今回結果ではない**（基準/凡例）→ ドロップ。
- **(B) name が基準表の見出し語**：`^(男性|女性|基準|基準値|年齢|新|従来)$`（完全一致）→ 実分析項目でない → ドロップ。

**アクション**：行ごとドロップ。**監査 `reason:'ref_table_row'`**。

**fail-safe**：レンジ/閾値が value 全体を占める行・「男性/女性」という項目名は、**いずれも今回測定値になり得ない**＝誤ドロップの心配がない安全な決定論条件。

**（将来・任意）上流除外**：`elith-export.ts` の scanArtifacts で「基準値表/相関図ページ（男女×年齢の基準マトリクス・散布図）」を**ページ分類してスキャン対象から外す**。当面は本 G3 の後段ゲートで足りる（捏造ゼロ優先）。

**実装箇所**：`sanitizeMeasurementsForDelivery` 冒頭のフィルタ。**env**：`SCAN_FABGATE_REFTABLE`（G2 と同一フラグに束ねても可）。

## 4. ゲート G4（任意・低信頼＝当面は監査のみ）：隣接項目値の漏れ

**問題**：体脂肪率=26.5（＝BMI 値の漏れ込み・今回=空）。

**課題**：体脂肪率≈26.5% は BMI 26.5 と**偶然一致し得る**（物理的に別概念だが値域が重なる）。厳密ドロップは真値誤削除リスク。

**方針**：**自動ドロップしない**。`体脂肪率.value_num == BMI.value_num`（同一検査票）を **監査 `reason:'adjacent_leak_suspect'` で可視化のみ**（admin 表示）。恒久策は列来歴（P-perc の領域照合）待ち。**env**：`SCAN_FABGATE_ADJACENT`（既定 off・監査専用）。
