## 0. 最上位ゴールと、設計思想の位置づけ（重要・優先順位）

- **最終ゴール（絶対）**: 検査票 → 正確な JSON（漏れなし・捏造なし・余剰なし）→ Elith → 高精度診断。
- **設計思想（手段・従属）**: 多様なフォーマットに **ネイティブマルチモーダル LLM** を活かし、昭和の OCR 的レイアウト・パターンマッチ（テンプレOCR）を使わない。
- **優先順位**: 設計思想はゴール達成のための"最良と信じた手段"であって、ゴールそのものではない。
  **手段でゴールに得点できるなら維持。著しく得点率が低いなら、確実に得点する手段へ変える（ゴールが勝つ）。**
  「パターンマッチ禁止」を得点の足枷にしない。

---

## 1. 業界事実（一次資料で確認・R3）

- **紙/PDF の見た目（レイアウト）に支配的な統一標準は無い**。健診機関ごとにバラバラ、様式は機関裁量で変更される。
  → **読取（Perception）はテンプレOCR不可能 → ネイティブマルチモーダルが正解**。
- **一方、"電子データ構造"の業界標準は存在する = 「健診標準フォーマット」(KMAT)**。
  - 策定・推進: **日本医学健康管理評価協議会**（日本人間ドック学会・日本医師会ら健診関係10団体）。
  - 特徴: CSV・**標準用語(名称)ベース**（原則コードでなく標準名称）、**判定名称/記号(未満・以上)/標準用語の統一**、画像所見も用語リストで標準化。特定健診にも対応。
  - 規模: 最新 **KMAT ver5.0 ≒ 約2000項目**（2025/2）。2025時点 **725施設**採用。
  - 維持運用: 2026年度以降 **一般社団法人 日本医学健康管理推進機構（HASTOS / hastos.jp、商用2025/4〜）**。
- **業界の主流アプローチ**: バラバラの見た目を **システム側でこの標準データへ強制変換（マッピング）**（例: Carely / Be Health、推進機構の変換ソフト）。

> 出典: 健診標準（www.kenshin-hyojun.jp）、日本医学健康管理評価協議会 KMAT ver3.2/ver5.0 説明資料、厚労省 健診標準フォーマット普及資料、HASTOS（hastos.jp / faq.hastos.org）。**完全な用語リスト（約2000項目・単位・判定）は推進機構/HASTOS への照会 or クライアント/Elith 経由で入手する（当社で捏造しない）。**

## 2. 戦略：2層に分ける（矛盾は「読取」と「正準化」を分けると消える）

| 層 | 方式 | 設計思想との関係 | 担当する得点 |
|---|---|---|---|
| **① 読取 (Perception)** | ネイティブマルチモーダル LLM（**現行維持**） | レイアウト多様 → **思想通り正しい**。テンプレ化しない。 | 紙面 → 忠実な転記（値・単位・基準・判定の生読み） |
| **② 正準化 (Normalize/Map)** | **「健診標準フォーマット」への決定論マッピング**（**新規**） | 標的は**1つの標準マスタ**（レイアウト別テンプレではない）＝**汎化しない負債ではない**。業界標準そのもの。 | 名寄せ・単位・判定の統一、余剰/不足の判定 |

**②は"昭和のOCRパターンマッチ"ではない**: ピクセル/レイアウトを照合するのでなく、LLM が自由に読んだ**意味（項目名/単位/判定）を統制語彙（標準マスタ）へ写像**する。現代の医療データ連携の標準手法で、「OCRを使わない」思想と矛盾しない。

**設計思想との非衝突**: 思想が禁じたのは「読取のためのレイアウト・テンプレOCR」であって、「出力の標準正準化」ではない。②は思想の対象外であり、ゴールに直接得点する。

## 3. ②正準化がゴールの"得点の穴"をどう埋めるか

| 観測された穴（🎯で実測） | ②標準マスタ・マッピングでの解決 |
|---|---|
| 名寄せ（尿酸↔痛風 / 中性脂肪↔TC / 白血球↔白血球数） | 標準項目名＋同義語マスタで写像。**section/detail のどちらが分析名かを推測せず、両方を標準マスタに照合しヒットした方を正準名に**（`pickDeliveryName` の当て推量を廃す・決定論） |
| 単位ゆれ（mg/dl↔g/l, cm↔m） | 標準単位＋換算表 |
| 判定ゆれ（A〜E, 記号 未満/以上） | 標準判定へ正規化 |
| **不要データを渡さない（余剰排除）** | 標準マスタ（=Elith 必要サブセット）に**無い項目はフラグ提示**（`elith-necessity-check` 既存設計＝自動削除でなく提示）。**不足も"deficient"として検出** |
| Elith 診断精度 | **標準項目名・標準単位の綺麗なデータ**が渡る → 精度直結 |

**読取の検出揺れ（定性(-)/K-W/時系列リーク）は②でなく①の問題** → 既存 **VQA 第2パス**（`SCAN_BOUNDARY_RECHECK`）が担当（直交レイヤー）。VQA でも読めない画像固有のあいまい（K-W "0"）は**空のまま＝捏造ゼロが正解**。

## 4.5 処理モデル：テンプレート穴埋め方式（②の具体化・実装計画）

②正準化の処理は「出力側を後追いで整形」ではなく、**出力の形（標準の項目名・単位）を先に固定した空テンプレートへ読取値を流し込む**モデルで行う。要旨は【元画像の検査結果を、正確に（漏れなく・捏造なく・不要は落として）業界標準の項目名・単位で、Elith と決めた JSON にする】。

- **S1** 空テンプレート生成（標準マスタ §2.4 から {標準名, 標準単位, ref, value=null} のスロット集合）
- **S2** 穴埋め（①読取＋sanitize 済 measurement を名寄せ/単位換算し、**高信頼時のみ**スロットへ代入。非ヒットは元名のまま通す＝捨てない・別項目に当てない）
- **S3** 移植カバレッジ照合（未写像＝surplus として**記録**・silent drop しない／必須スロット空＝deficient）
- **S4** 空スロット削除（当該検体で未実施のスロットは納品除外＝既存 `sanitizeMeasurementsForDelivery` に一致）
- **S5** Elith JSON 化（lean measurement ＋ エンベロープ）

**①読取との直交**: S2 で穴埋めする値は「今回列の値」でなければならない。3期間リーク（過去値の今回混入）が残ったまま②に入ると正しいスロットに誤値が入る（発見困難な False-Value）ため、**VQA 第2パス（①）で読取を正した後に②を通す**。②は読取値に触れない。

## 5. 実装方針（決定論・捏造ゼロ・保守的）

- **正準名/単位/判定は決定論マスタで**決める（LLM に判定・整形させない＝現行の集約原則 CLAUDE.md と一致）。
- **保守的マッピング**: 標準項目へ**高信頼で写像できた時だけ**正準化する。写像不能は**元のままフラグ**（強制変換で誤マップ＝捏造を作らない）。
- **漏れ防止**: マスタ外を**自動削除しない**（フラグ提示）。不足はブロック（deficient）。
- **監査**: 正準化の before/after（元名→標準名、元単位→標準単位）を監査ログに残す（Elith 納品 data には含めない）。

## 6. 期限を踏まえた段階導入

1. **①(読取)は変えない**。VQA 第2パスも維持（読取揺れ担当）。
2. **②を Elith 必要サブセットに絞って構築**（約2000項目を全部作らない）。ゴールデン検体の実項目＋Elith が使う範囲に限定。
3. **starter マスタ**: まず代表検体に出る**実在の標準項目**（尿酸・中性脂肪・白血球数 等＝捏造でない実名）で同義語/単位マップを小さく作り、**🎯で効果（名寄せ Missing 減・余剰減・回帰ゼロ）を検証**してから拡張。
4. **完全マスタ**は推進機構/HASTOS 照会 or クライアント/Elith 受領で差し替え（starter を権威データで置換）。

## 8. 却下・保留（履歴）

- **様式別プロンプト/テンプレOCR（レイアウト特定→様式別処理）= 却下**: 見た目に標準が無く様式は機関裁量で変わる → 保守地獄・汎化しない負債。②（標準1つへのマッピング）とは別物。
- **主パス(プロンプト)への時系列/定性規則の強化 = 不採用（実証済 numeric 回帰）**: 対策A（Missing 9）。読取揺れは VQA(①) で救済。
- **モデル階層 3.1-lite↔3.5 の格上げ = 不採用**: md段階で 3.5 が lite を上回らず（K-W・免疫便潜血を md 空にする）、課題未解決＋503 リスク。モデルはレバーでない。
