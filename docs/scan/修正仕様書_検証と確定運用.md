## 1. 現状（出典付き）

- `checkNecessity` は2箇所で使用：`elith-scan.ts:125`（`requiredItemsMaster` を **body 依存**で供給）と `hc-merge.ts:191`（**マスタ無し**）。→ **常時のマスタ供給が無い**。
- `elith-scan.ts:144` で不足（deficient）を既定で書出しブロック済（項目層が動けば機能する）。
- VQA：`boundaryRecheck`（`elith-export.ts:579`）が `VqaAuditEntry[]`（`elith-export.ts:553-559`・action=filled/overwritten/dropped/left_unresolved/vqa_error）を返し、per-part → hc-merge `vqa_audit` → admin `elith-batch.astro` で表示。**Phase 1/2 実装済・🎯検証待ち**（CLAUDE.md）。

## 2. 変更内容

### 2.1 `checkNecessity` へ既定マスタを供給

- `elith-scan.ts:122-125`：`body.requiredItems` が無ければ **`masterItemNames()`（`standard-master.ts`）を既定**に使う（body 指定があればそれを優先）。
- `hc-merge.ts:191`：`checkNecessity(jsonObj, { requiredItemsMaster: masterItemNames() })` に変更（構造チェックのみ→項目層も稼働）。
- **既定ブロック挙動の確認**：deficient で書出しブロック（`elith-scan.ts:144`）が starter マスタで過剰発火しないよう、**starter は「Elith 必須」だけに絞る**か、当面 deficient を**警告に留める**（ブロックは Elith サブセット確定後に厳格化）。→ 要確認事項（§5）。

### 2.2 カバレッジ監査の可視化（admin）

- 正準化エンジンの `mapped/unmapped/deficient`（`docs/scan/修正仕様書_正準化エンジン.md` §2.1）を、VQA 監査（`vqa_audit`）と同じ経路で per-part 応答に載せ、`elith-batch.astro` に表示：
  - **写像 (mapped)**：元名→標準名／元単位→標準単位（何を正準化したか）。
  - **未写像 (unmapped)**：マスタ外＝surplus 候補（**自動削除でなく提示**。漏れ検知）。
  - **不足 (deficient)**：必須マスタにあるのに値が無い。
- **Elith 納品 data には含めない**（監査のみ。基本設定書 §3.6.1 の原則）。

### 2.3 VQA Phase 1/2 の🎯検証（①レイヤ・実装済の検証）

- **第2検体ゴールデンの追加**：眼圧・血清（RPR/TP）が**"実施済"**の検体を `scan_golden_*` に追加し、「timeline_leak 削除が実施済を落とさない（Missing 0）」を確認（CLAUDE.md Phase 2 の残リスク対処）。
- 確認軸（`docs/scan/golden/scan_golden_healthcheckup_20250123.md` §サルベージ/VQA 4象限）：
  - ①実施済(正常) → value 保持（Missing 0）
  - ③未実施の罠（RPR/TP=基準(-)・今回空） → 空（False-Value 0・最重要）
  - timeline_leak（眼圧 今回空＋過去16） → 削除される（False-Value 0）、ただし**実施済眼圧は削除しない**。

### 2.4 回帰ゲート（CI 的手順）

正準化 on・VQA on で `scan_golden_*` を再RUN→`elith-batch.astro goldenCheck`：
- Missing Value Rate / Column-Shift Rate / **False-Value Rate=0** / 定性一致率 / Semantic-Tie(残)。
- **numeric 全一致**（正準化 on/off 差分ゼロ）。差分が出たら on にしない。

### 2.5 確定運用の更新（基本設定書 §3.8 / CLAUDE.md）

🎯ゲート通過後：
- 本番スキャン ＝ `SCAN_OUTPUT_FORMAT` 未設定(=markdown) + `SCAN_BOUNDARY_RECHECK=on` + **`SCAN_CANONICALIZE=on`**。
- `docs/scan/基本設定書.md §3.8` と `CLAUDE.md「確定運用」` を更新（決定が変わったら doc を更新・CLAUDE.md 作業ルール3）。
