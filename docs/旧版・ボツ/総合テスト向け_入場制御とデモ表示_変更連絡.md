## 2. 変更点

### 2-1. デモ表示の判定順序を変えた（`src/lib/demo-data.ts`）

**これが今回の実質的な修正です。**

```
旧: ① env PUBLIC_DEMO_FALLBACK !== 'false'  かつ  ② uid が admin      … AND（env が先）
新: ① uid が admin なら true（env で塞がない）
    ② env が 'false' なら false（admin 以外を一括で切る）
    ③ DEMO_ALLOWED_UIDS（OEM デモ顧客）
```

**旧実装は本番で `PUBLIC_DEMO_FALLBACK=false` を入れると admin まで塞がれていました。**
その結果 `/report` が「主軸の帯と主軸 A の 1 枚だけ」の状態になります（実測）。
これでは `13a8a95` が宣言した「デモ表示を **admin 限定** にする」の admin 限定の枝が本番で死にます。

> **順序が要件そのものです。** `env` を先に戻すと admin が全画面ほぼ空になります。

### 2-2. 管理者登録を 1 箇所に統合した（`src/lib/admin-auth.ts`）

統合前は `ADMIN_EMAILS`(7 件) と `ADMIN_UIDS`(7 件) の **手書き 2 本** が並んでいて、対応が取れていませんでした。
さらに実測すると、**アプリの admin 判定は uid 側しか見ておらず、`isAdminEmail` と `gateByUid` は参照ゼロの死んだコード**でした。

→ **email 側に足しただけでは admin になりません。** 足した人は登録したつもりになります。
管理者は今後追加されていくので、この罠を潰しました。

```ts
// src/lib/admin-auth.ts — admin を足すときはここだけを直す
export const ADMIN_MEMBERS: readonly AdminMember[] = [
  { label: '濱田', email: 'unfix.hamada@gmail.com', uid: '14410d5a-…' },
  …
];
```

- **追加は 1 行**（`{ label, email, uid }`）。`ADMIN_EMAILS` / `ADMIN_UIDS` はここからの**導出**
- **uid が判定の実体。** uid は当人の `/dashboard` →「デバッグ（テストフェーズ確認用）」に出ている `diagnostic_user_id`
- **uid が分からなければ `uid: null` で登録してよい。** `npm run verify:demo-gate` が
  「uid 未登録のため admin として扱われません」と**名指しする**ので、黙って非 admin のまま放置されない

> **⚠ 現状 8 名中 1 名が uid 未登録です** — `開発用バックアップ`（`hamada@eentry.co.jp`）。
> ただし **email が登録されていればサインインし直すだけで admin になります**（uid は不要）。
> uid も埋めておくと `?u=` 入場など Cookie 以外の経路でも admin になります。

### 「admin にならない」の切り分けは画面でしてください

**推測しないでください。`/dashboard` の「デバッグ（テストフェーズ確認用）」に出ます。**

| 表示 | 意味 |
|---|---|
| `admin 判定: ✓ admin（根拠: サインイン時の email）` | email で成立。uid は見ていない |
| `admin 判定: ✓ admin（根拠: uid が登録済み）` | uid で成立 |
| `admin 判定: ✗ admin ではない（この uid も、サインインした email も ADMIN_MEMBERS に無い）` | **登録簿にそのアカウントが無い。** email を 1 行足せば解決 |
| `デモ表示: 出す / 出さない` | 上の判定の結果 |

### 2-3. 受領 JSON を実データとして入れるスクリプトを追加（`scripts/ingest-elith-report.mjs`）

デモではなく**本物として**紙面を出したいとき用です。既存の `POST /api/admin/elith-report/upload` を叩くだけで、
**admin 取込画面は作っていません**（発注者指示）。

```
node scripts/ingest-elith-report.mjs --uid <diagnostic_user_id> --key <ADMIN_API_KEY>
```

- 送るのはリポジトリ同梱の受領 2026-08-26 分。**中身は 1 バイトも加工しない**
- `ADMIN_API_KEY` は **Vercel の環境変数が正**。スクリプトはどこにも保存しない
- **世代管理あり**（既存行を `superseded` に落として新しい行を足す）。何度流しても表示は最新 1 件

## 2-4. admin 判定は email からも成立する【追加・`a7835d7`】

> **順序を直しても本番の `/report` は空のままでした。**
> 真因は **admin 判定の実体が uid だけ**だったこと。管理者リストに email で載っているメンバーが
> admin にならず、**要件に対してリストの半分（email）を実装が読めていませんでした。**

**サインイン時に、サーバで検証済みの email から admin を判定し、署名付き Cookie に載せます。**

| 項目 | 内容 |
|---|---|
| 判定の場所 | `api/auth/resolve.ts` — `signViewer(uid, isAdminEmail(email))` |
| email の出どころ | `sb.auth.getUser(accessToken)` で**サーバが検証した値**。クライアントの申告ではない |
| 改竄耐性 | admin フラグを payload に含めて HMAC。`0`→`1` は**署名不一致で棄却** |
| 旧 Cookie | `uid.exp.sig` の 3 分割も**受ける**。**再サインインを全員に強いない** |
| 成立条件 | Cookie の admin **または** uid が `ADMIN_MEMBERS.uid` に在る |

**`ADMIN_MEMBERS` に email を 1 行足すだけで admin として扱えます**（uid を調べる必要がない）。
uid も埋めておくと `?u=` 入場など Cookie 以外の経路でも admin になります。

閲覧者フラグは画面から判定関数まで引き回しています。`demoFallbackEnabled(uid, viewerIsAdmin)` の
第 2 引数は**任意なので渡し忘れても型では落ちません** → `verify:demo-gate` が**渡し忘れを機械で検出**します
（導入時に実際に 1 件検出）。**代理表示中（`?u=`）は渡しません**＝相手の実データを見せます。

> **⚠ dev 限定の落とし穴。** `PUBLIC_GOOGLE_CLIENT_ID` が未設定だと `authEnabled=false` になり、
> 未サインインでも `DEFAULT_USER`（`d0000001`＝**admin uid**）に落ちてデモが出ます。
> **本番は認証有効なのでこの経路に入りません**が、ローカル検証では紛らわしいので
> `PUBLIC_GOOGLE_CLIENT_ID` を入れて確認してください。

### 認証を有効にした最終確認

| 閲覧者 | カード見出し | Elith 本文の語 |
|---|---|---|
| **admin（email 登録のみ・uid 未登録）** | **42** | 出る |
| 一般顧客（admin でない） | 1 | **0** |
| 一般顧客が admin フラグを改竄 | 1 | **0** |
| 未サインイン | 1 | **0** |

署名まわりは単体でも検証済み — 改竄（フラグ / uid / 期限）3 種とも棄却、期限切れ棄却、旧 3 分割互換。

  （デモは `demo-data.ts` のコード内定数と受領 JSON で、**DB を経由しない**）。

## 4. 回帰チェックを追加しました

```
npm run verify:demo-gate      # 単体
npm run verify:report         # report 系とまとめて（demo-gate を同梱）
```

出るもの:

1. **管理者メンバーの棚卸し** — 誰が登録済みで、誰が uid 未登録か
2. **誰にダミーを出すかの表** — admin / 一般顧客 / 未サインイン / OEM デモ顧客 × env の 2 値
3. **判定の順序チェック** — ①admin → ②env → ③許可 uid の順になっているか

> ここは**静かに壊れます**。判定が 1 つ変わるだけで、**admin が全画面ほぼ空になる**か、
> 逆に**実顧客へ他人名義のダミーが「自分の結果」として出る**かのどちらかが起き、
> **どちらも画面を見ただけでは気づけません**。だから表で固定しました。
> **順序を旧に戻すと落ちること**も確認済みです。
