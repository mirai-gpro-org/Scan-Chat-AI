# 修正案（Phase 1＋2）確認依頼 ― 証拠付き Observation 生成パイプライン

前回相談（多様な健診様式での numeric 完全性・課題 A/B/C）への **Gemini / ChatGPT 両者の助言を統合**し、下記の修正案（Phase 1＋2）にまとめました。
**実装着手前に、この設計の妥当性・失敗モード・順序・実現性を確認**してください。事実のみ記載します。**人手を前提にした回答は要件違反として不可。**

---

## 0. 依頼
- この統合設計（Phase 1＝決定論の先行修正／Phase 2＝画像インベントリによる行欠落救済）に、**見落とし・失敗モード・より良い代替**があれば指摘してください。
- 特に **Phase 2（画像インベントリ）の堅牢性**と **Vercel 60秒予算での多段パスの現実性**を重点的に。

## 1. 背景（確定事項）
3 課題は別々のバグでなく、**「値の抽出」と「行・領域の存在確認」をモデルに同時に委ねている**ことから生じる共通の構造問題、と結論しました。
- **A**：numeric の行ごと欠落（例：人間ドックで FT3=3.1 が raw に**一切存在しない**＝隣接セルへの吸収ではなく行の脱落）。
- **B**：「検査結果の推移」トレンドグラフ section を measurement 抽出し、**前回値の混入＋重複**（内臓脂肪108.0/正140.3・LDL102/正129・TG129/正82・血糖100/正101・HbA1c5.4/正5.7）。
- **C**：多テーブル様式（rows 88〜109）の**別名重複**（最高血圧×2 / 尿蛋白定性 vs 蛋白 / 尿潜血定性 vs 潜血 / 免疫便潜血×2）。

**既実装（ベースライン）**：①読取＝native multimodal・10列Markdown・temp0・**プロンプト凍結**。決定論後段＋局所VQA第2パス（眼圧の過去値混入を**行クロップで削除**／定性(-)充填／別名dedup／ダッシュ正規化／採点器の列取り違え除外）。**眼圧の誤削除ゲートは複数の実施済検体でPASS**。

**制約（厳守）**：①プロンプト凍結（強化＝numeric回帰の実績）／**捏造ゼロ最優先**／**人手100%不可**（全自動）／**1画像=1リクエスト・Vercel 60s**／`gemini-3.1-flash-lite`・temp0／追加依存は最小（画像処理 `sharp` 導入済）／**様式は4種以上と多様**／数学的100%は確率モデル単体では不可＝目標は「人手ゼロ・捏造ゼロで漏れ/余剰/誤りを限りなく0」。

## 2. 中核原則（設計の転換）
- **出力の根拠は「画像内の存在証拠」**。マスタ(KMAT)が「あるはず」と言うから読むのではなく、**画像にラベルが実在し同じ行に今回列がある行だけ**を充填する（＝捏造ゼロを構造的に担保）。
- **マスタ3層**：① 共通項目マスタ（KMAT/厚労省標準/必要に応じ LOINC）② 施設・様式プロファイル ③ 当該画像インベントリ。**出力の根拠にできるのは ③ のみ。①② は再読対象を見つける照合・正規化に限定**。

## 3. 修正後アーキテクチャ（全体）
```
1  画像正規化（回転・傾き・コントラスト・解像度）
2  領域分類（measurement_table / trend_graph / summary / judgement / narrative / reference_range / unknown） … Phase1(B)
3  グラフマスク（trend_graph を主パス用画像コピーから白塗り除外・fail-close）              … Phase1(B)
4  主パス（現行の凍結 Gemini 読取）                                                        … 既存
5  行インベントリ（measurement_table 内の全行候補を列挙＋座標）                            … Phase2(A)
6  カバレッジ照合（主パス出力 vs 画像内行候補）                                            … Phase2(A)
7  局所VQA（画像に存在する不足行のみクロップ再読）                                          … Phase2(A)
8  正規化（canonical code・検体・単位・値型・今回/前回）                                    … Phase2＋既存canonicalize
9  dedup・競合解決（複合ID＋出典優先＋監査）                                                … Phase1(C)
10 完全性監査（全行に終了状態・不変条件）                                                  … Phase1(共通)
11 Elith 連携（証拠がある確定値のみ push）
```

### Phase 1（決定論・低リスク・先行実装）
**B 領域除外（グラフ混入の遮断）**
- trend_graph 判定は**見出し単独に依存しない**：`見出し(検査結果の推移/経年変化/推移)` ＋ `画像幾何(軸/目盛/マーカー/凡例/時系列ラベルの横並び/低文字密度)` の**複合2条件以上**。
- trend_graph からは measurement を**一切生成しない**。曖昧領域は `unknown_region` として隔離（**fail-close**）。
- 実装：主パス前の `sharp` マスク、または後段の section 除外。**見出し文字だけの除外は禁止**（通常表内の小型判定図を誤除外し得るため）。

**C 複合IDによる決定論 dedup**
- 同一性キー＝ `canonical_test_code + specimen + body_site + method_or_qualifier + laterality + value_type + time_role`。
  - 例：`白血球数(blood, quantitative, current)` ≠ `白血球(urine_sediment, microscopy, current)` ＝**別ID（統合しない）**。
  - 例：`尿蛋白定性` ≡ `蛋白`（同 section・定性・今回）＝統合候補。
- 決定規則：値一致→1件統合（出典座標を保持）／値相違→**出典優先順位**（`詳細表 > 専用結果欄 > 総合判定 > サマリー > 推移グラフ`）で採用し、**rejected_candidates を監査に残す（黙って消さない）**／検体・測定法不明→統合せず別候補のまま／グラフ由来→measurement から除外。

**完全性アカウンティング（no silent drop の可観測化）**
- 各行に終了状態：`EMITTED / EMPTY_PRESENT / UNREADABLE / EXCLUDED_GRAPH / NON_MEASUREMENT / CONFLICT_REJECTED`。
- 不変条件：`検出行数 = 出力 + 空欄 + 読取不能 + 除外 + 非検査 + 競合却下`。
- 文書状態：`completeness_status(complete_by_evidence / partial_unresolved)`、`unresolved_row_count`、`graph_leak_count` 等。**未解決行があれば完全扱いで Elith へ送らない**。

### Phase 2（本命・重い・A の解決）
**A 画像インベントリ＋証拠限定VQA**
1. `sharp` で行候補検出（水平罫線／テキスト密度の谷／行間の白／左端の項目名領域）→ 各行に `row_id`＋座標。
2. **補助パスは値を読ませず項目名のみ抽出**（主パスと異なる失敗モードにする）。
3. 主パスの項目名と照合 → **「画像に項目名があるが主パスに無い行」だけ**をクロップ。
4. 局所VQAで今回値を読む。充填は **AND 条件**：
   `label_evidence == true AND row_bbox_exists == true AND current_column_exists == true AND primary_output_missing == true`
5. 値が不鮮明なら埋めず `null / unreadable`（**捏造しない**）。局所クロップ再読時のみ高解像度を検討（60s とのバランス）。
6. KMAT は正規化・別名解決に使用（**出力根拠にはしない**）。

## 4. 実現性の論点（重点的に確認したい）
- **画像インベントリ(CV)の堅牢性**：傾き・淡い罫線・写真ノイズ（＝まさに問題が起きる条件）で行検出が外れると、FT3 の存在を棚卸しできず救えない。堅くする方法／フォールバック（例：補助ラベルパスとの二重化）は。
- **60s / 1req 予算**：領域分類＋インベントリ＋補助ラベルパス＋局所VQA×N を、人間ドック（rows 100+）で 60 秒内に収める段取り（クライアント逐次呼び・どのステップを1コールに束ねるか・並列可否）。
- **temp 方針**：本番 temp0 を維持しつつ、temp1.0 を**同一回帰セットでシャドー並走**し、行欠落率・余剰率・誤読率（**numeric recall を主指標**）で別々に比較。この方針で妥当か。

## 5. 聞きたいこと（効果が大きい順に・基本設計レベルで）
1. この統合アーキテクチャ（**証拠優先インベントリ＋複合ID＋完全性アカウンティング**）に、見落とし・失敗モード・より単純で堅い代替はあるか。
2. **順序**（Phase1＝B/C/完全性を先行 → Phase2＝A インベントリ）は妥当か。60s・実装コストの観点で。
3. **画像インベントリ(A)の堅牢化とフォールバック**設計。CV が外した行をどう二重で拾うか。
4. **60s 予算内での多段パスの現実的な束ね方**（どこを1コールに、どこをクライアント逐次に）。
5. 実装前に**足す/削るべき点**。
