## 1. 両レビューの要点（事実）

**レビューX（前回案の Phase 2 に対して）**
- Phase 2 の CV（画像処理）による行検出は、傾き・影・淡い罫線で外れる **SPOF**。→ 行座標特定は CV でなく **LLM の bbox 空間認識**に委ねよ（「全ラベル名＋bbox、値は読むな」）。
- 60s 制約は**クライアント主導の3リクエスト分割**で越える（主パス→インベントリ→局所VQA を別 req に）。
- グラフマスクで隔離した領域は破棄せず、完全性監査で Missing が出た時だけ局所VQA する**最終サルベージ用に保持**。
- 局所クロップは文脈喪失を起こす→**メタデータをテキスト補完**＋bbox に**+5% padding**。
- アンチパターン：「探す」と「読む」を1プロンプトに同居させない。conflict rejected をサイレント破棄しない。

**レビューY（中心命題そのものに対して）**
- **中心命題を「行欠落」から「ページ単位の時系列軸（列帰属）の誤認」に修正すべき**。
  - 実例（尿酸）：行は存在し画像の `7.8` も備考に取り込まれているが、**今回 7.8→前回と誤認／前回 7.7→前々回／前々回 6.9→消失**。同一ページで**今回値が存在した3項目すべてが脱落**＝項目ごとの偶発ではなく**ページ全体の列マッピング失敗**を示唆。
  - 有力仮説：当該ページは**今回列にヘッダ日付が無く**、過去列に日付あり、今回欄の大部分が空・実値3行のみ→モデルが「日付の無い列は結果列でない／今回はほぼ未実施」という**ページレベル解釈**を形成し実値を過去側へ寄せた。（「疎→脱落」の因果はまだ確定でなく有力仮説。）
- したがって「行インベントリ＋不足行再読」だけでは尿酸を解決できない（尿酸行は既に存在するため）。
- **完全性の基準を「期待項目一覧」でなく「今回列に実在するインク・文字成分」に置く**：
  `今回列セルにインクあり AND JSON今回値なし → 必ず再読`。allow-list に無くても検出できる。
- セル占有判定は**値を読まない**（罫線除外の前景画素・連結成分・数字寸法・赤彩度[↑↓]・隣接ノイズ比較）。「何か印字されているか」だけを判定＝捏造でない。
- 4条件（人手ゼロ・捏造ゼロ・必ず納品・必ず完全）は**同時保証不可**。保証可能なのは**人手ゼロ・捏造ゼロ・サイレント脱落ゼロ**で、証明できない文書は自動停止。
- アンチパターン：numeric を allow-list に足し続ける／項目単位で対処／疎ページ用の別巨大プロンプト／全ページ2回読んで多数決／KMAT の期待項目で値補完／備考の数字を今回値へ移す／基準値・前回差から今回値を推測／モデルの「今回欄に値なし」説明を証拠採用。

## 2. 統合で確定した点（妥当性を確認してください）

### 2-1. 中心命題の修正（両レビュー整合）
- 失敗モードは**2種が両方実在**する、と整理し直しました：
  - **列帰属失敗**（尿酸）：行もラベルも値も存在するが、今回値が過去列へ誤帰属。
  - **真の行欠落**（別サンプルの FT3=3.1）：raw markdown に行が**一切存在しない**（TSH と FT4 の間が欠落）。
- **レビューX の「ラベル bbox インベントリ」単独では列帰属失敗（尿酸）を救えない**：ラベルも値も画像・JSON 双方に在るため「尿酸あり→OK」で通過する。列がズレているだけだから。

### 2-2. 統一 primitive ＝「今回列セル存在検証」（label-inventory を包含）
- レビューY の `今回列セル占有 AND JSON今回値なし → 要再読` は、**列帰属失敗と行欠落の両方を1機構で捕捉**できる（行が丸ごと落ちても、今回列セルにインクがあり対応 JSON 値が無ければ発火）。
- よって統一 primitive は「ラベル・インベントリ」ではなく**「今回列セル・インベントリ」**を採る。**要確認：この包含関係の理解で正しいか。**

### 2-3. CV / LLM の責務分界（両レビューの対立の解消）
- レビューX（CV は脆弱→LLM bbox）とレビューY（CV でセル占有判定）は、**「CV に何をさせるか」で解けると解釈**しました：
  - **列/行の幾何（今回列 x 座標・行 bbox）＝ LLM の空間認識**（傾きに強い）。
  - **各今回セルの占有＝インク有無の二値判定のみ CV**（値は読ませない＝頑健）。
  - **JSON との突合・対応付け＝決定論コード**。
- すなわち「CV に**値を読ませない**」限り CV セル占有判定は堅く、レビューX の SPOF 懸念（＝CV に読取を負わせるな）と両立する。**要確認：この分界で SPOF を回避できるか。**

### 2-4. ページ「列軸マップ」を新層として追加（レビューY 第1位）
- 今回/前回/前々回/基準値/単位の**列 x 座標をページ単位で確定**し、LLM の時系列判断から独立させる。
- 今回列に日付が無くても「基準値列の右・最初の日付付き過去列の左」で今回列を特定。
- これにより現行の `timeline_leak`（眼圧・血清だけの**項目 allow-list**：レビューY のアンチパターンに該当）を廃し、**項目固有ルール無し**で尿酸・免疫便潜血を同一機構で拾う。**要確認：allow-list 全廃で回帰リスクは無いか。**

### 2-5. その他採用（レビューX）
- 3リクエスト分割（主パス／セル・インベントリ＋列軸マップ／局所VQA）＝既存の「1画像=1 Vercel リクエスト・クライアント逐次」に整合。
- グラフマスク領域のサルベージ保持。局所クロップに**過去列を含めない**（レビューY）＋列見出しメタデータ補完＋bbox に padding（レビューX）。

## 3. 未決定 ― 完全性ポリシー（判定してください）
4条件同時保証は不可（レビューY）に同意。保証は「人手ゼロ・捏造ゼロ・**サイレント脱落ゼロ**」とする。
問題は**「今回列セルにインクありだが、自動リトライラダー（元クロップ→コントラスト強調→2倍拡大→赤成分保持）でも値が読めない文書」の扱い**。人手介入は不可なので、下記いずれか：

- **案1：部分納品＋ unresolved マーカー**
  読めた値は納品し、未解決セルを**機械可読フラグ**（`row_id / bbox / status=UNRESOLVED`）で Elith に明示。下流（Elith）が欠測として扱う。文書は止めない・サイレント脱落は起きない。
- **案2：文書ごと自動保留（AUTO_REJECTED・納品しない）**
  未解決セルが1つでも残る文書は Elith へ送らず自動保留。ただし人手ゼロだと保留文書は自動再RUN 以外で解消されない。

**聞きたいこと**：医療データで「サイレント脱落ゼロ」を満たしつつ**全自動を崩さない**なら、案1と案2のどちらが整合的か。第3の案（例：セル単位で確定分のみ EMITTED＋未解決は明示的 UNRESOLVED として同一文書内に共存させ、文書自体は通す）はあるか。Elith 側が欠測フラグを解釈できる前提の是非も含めて。

## 4. 事実訂正（母数の統一）
過去相談で `numeric 29/29` と `今回値一致 31/34` が併存していましたが、これは**別サンプル・別ゴールデン定義**の数字です（29/29＝2025-01-23 の5枚×2run の numeric 一致数／31/34＝別様式サンプルの今回値一致・Missing 3）。同一文書内の矛盾ではありません。今後は母数をサンプルごとに明記します。
