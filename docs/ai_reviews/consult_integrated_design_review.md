# 統合設計案レビュー依頼 ― 疎ページの「今回セル脱落」を人手ゼロ・捏造ゼロで潰す

前回の焦点化資料（元画像③-4 / Reader の Markdown / 「今回列だけ実測3セルが全滅」）へのご助言を、**両モデルの回答を統合して 1 つの設計案**にまとめました。
本書はその **統合設計案を、忌憚なく批判的にレビュー**していただくための依頼です。欠陥・失敗モード・見落とし・より単純で堅い代替を指摘してください。

> **要件（厳守）**：人手介入は 100% 不可（「数%だけ人手」「要確認フラグで人送り」も一切不可）。**数学的な Missing=0 保証は確率モデルでは不可能**という前回のご指摘は受け入れます。したがって本設計の目標は「**人手ゼロ・捏造ゼロで Missing を限りなく 0 に近づけ、真の残差は"空"のまま（誤値も人手も出さない）**」です。**人手を前提にした回答は要件違反として不可。**

---

## 1. 対象問題（1 事象・再掲）

- 疎ページ③-4（血清/脈波/肺機能/ABC/痛風/肝炎）は**「今回」列がほぼ全欄空**。実測値のある行は **尿酸=7.8(↑) / 免疫便潜血 1日目=(-) / 2日目=(-)** の 3 つだけ。
- この RUN では **その 3 セルが全て Reader(md) 段階で脱落**（尿酸の 7.8 は備考に「前回7.8」と文字だけ残存＝今回値としては消失）。
- 原因の見立て（両モデル一致）：**OCR 誤読でも幾何学的な列ズレでもなく、「このページは今回列に実測がほぼ無い」というページ全体の高次判断（内部仮説）**に引きずられ、残る実測セルまで空と解釈した。

## 2. 絶対制約（再掲）

- **① Reader のプロンプトは凍結**（強化＝別ページ numeric 全壊の実証済み回帰）。
- **捏造ゼロ**（読めない値を 平均/前回値/基準値 で埋めない）。
- **人手介入 100% 不可**（全自動）。
- **1 画像 = 1 リクエスト・Vercel 60s**。モデル `gemini-3.1-flash-lite`・`temperature:0`。
- **追加依存は最小**。
- **規模は 1 検体あたり約 40 項目**（大規模統計でなく、数十項目を漏れなく確定する問題）。

---

## 3. 統合設計案（本体）

### データフロー
```
画像
  │
  ▼
① Reader（現状維持・凍結）           … ページ全体を 10列Markdown へ構造化
  │
  ▼
② セル存在 Verifier（新）            … 「値」でなく「セル画像のインク有無」を見る
  │   ├─ 期待項目(マスタ)で今回値が空 → 該当セルに文字があるか判定
  │   ├─ インク無し = 未実施（正・スキップ）
  │   └─ インク有り = 脱落候補（→ ③）
  ▼
③ セル単位 Repair（新・グラウンディング） … 脱落候補セルだけを局所再読
  │   ├─ そのセルだけを局所化（クロップ or bbox）して限定プロンプトで再読
  │   ├─ 読めた時だけ充填 / 読めない・空なら空維持（捏造ゼロ）
  │   └─ ページ全体を渡さない → 「今回列は空」バイアスを回避
  ▼
④ KMAT 正準化（現状維持）            … 名寄せ・単位・判定・余剰/不足
```

### 各層の責務

- **① Reader**：変更なし。10列 Markdown、`temp:0`、プロンプト不変。
- **② セル存在 Verifier（新）**：
  - ページ別の**期待項目マスタ**を基に、Reader 出力で「今回値が空」の期待項目を抽出。
  - その項目の**画像上の今回セルに文字（インク）があるか**だけを判定する（**値の意味は読まない＝捏造しない**）。
  - **インク無し＝未実施（空が正・スキップ）／インク有り＝脱落候補**。→ ここで「未実施」と「脱落」を**画像で**分ける。
  - 補助トリガー：Reader の**行内に孤立した数値が残っている**場合も脱落候補に加える（安価・任意）。ただし**採否は③が画像で決める**（テキストで確定しない）。
- **③ セル単位 Repair（新）**：
  - 脱落候補セル**だけ**を対象に、**そのセル画像を局所化**して限定プロンプトで再読：
    > 「これは〈項目名〉行の"今回"セルの画像です。返答は 数値 / (-) / (+) / 空 のいずれかのみ。推測禁止。値があるなら bbox も返す。」
  - **読めた時だけ充填。読めない・空・集合外なら空維持**（捏造ゼロ）。
  - **Reader（ページ全体）と Repair（局所セル）で認識経路を変える**＝失敗モードを非相関にし、**同一セルの二重見落とし確率を下げる**。
- **④ KMAT 正準化**：変更なし。

### フェイルセーフ
- ③で確認できない残差は**空**（誤値も人手も出さない）。**numeric もこの経路に載せる**（従来 Verifier/VQA は定性・時系列リークのみ対象だった＝これが今回の穴）。

## 4. 未決の設計判断（ここに意見が欲しい）

1. **セル局所化の手段**：
   - (a) **物理クロップ**＝画像処理依存（`sharp` 等）を追加。ページバイアスを完全排除。
   - (b) **全画像＋「このセルだけ読め」プロンプト**＝依存ゼロだがページ文脈が残りバイアス低減効果が薄い。
   - 60s / 1req / 追加依存最小 の下で、どちらが妥当か。折衷案は？
2. **② インク判定の実装**：VLM に「このセルは空か文字ありか」を問う（LLM 往復追加）か、軽量な画像処理（セル領域の非白画素比）か。後者は依存が要る。どちらが堅いか。
3. **コスト/レイテンシ**：脱落候補は疎ページで多くなり得る。60s / 1req に収めるため、**②③を 1 回の呼び出しで複数セル一括**にすべきか（一括にするとセル局所化＝バイアス回避の利点が薄れないか）。
4. **bbox グラウンディングの信頼性**：Gemini / GPT で座標出力は実用的に安定か。局所セルに対しても有効か。
5. **セル位置特定の依存**：クロップにはセル座標が要る。座標をどう得るか（Reader に bbox も出させる／別の locate 呼び出し／グリッド推定）。これ自体が疎ページで失敗しないか。

## 5. レビューしてほしい観点（効果が大きい順に 3 つ ＋ 特有注意 ＋ アンチパターン）

1. **この設計で本当に Missing → ほぼ 0（人手ゼロ・捏造ゼロ）に近づくか。** 残る失敗モードは何か。独立経路による二重見落とし低減は、実際どの程度効くか。
2. **② セル存在 Verifier の「インク判定」は、未実施と脱落を確実に分けられるか。** 誤判定（未実施をインク有りと誤る＝過剰 Repair／実測を空と誤る＝脱落見逃し）のリスクと対策。
3. **③ 局所 Repair の最小構成**（クロップ vs プロンプト・bbox・束ね方）の最適解。
4. 60s / 1req / 追加依存最小 の制約下での**現実的な構成**。
5. **見落としているレイヤー**、または**より単純で堅い代替設計**はあるか。

## 6. テストケース（具体）

- **尿酸**：今回=7.8（↑）/ 前回(2023/4/22)=7.7 / 前々回(2020/8/3)=6.9。**今回セルに印字あり**（＝②はインク有りと判定し③で 7.8 を回収できるべき）。
- **免疫便潜血 1日目/2日目**：今回=(-)（実施済）。**淡い定性記号で、run により備考にも何も残らない純粋検出漏れ**が起こる（＝②で「インク有り」と判定できるか、③で (-) を回収できるかが試金石）。
- **未実施項目**（肺活量・CAVI 等）：今回セルは真に空。**②がインク無しと判定し Repair をかけない**こと（捏造ゼロ）を確認。
