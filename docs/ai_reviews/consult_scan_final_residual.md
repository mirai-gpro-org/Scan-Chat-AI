## 1. 前回助言を受けて実施したこと & 結果（数値）

### (a) responseSchema(JSON mode)へ移行 → 検証の結果「不採用」
- 列帰属は安定した（Shift/Wrong 0）が、**補助フィールドが暴走**：
  - 未実施項目の `value` に**基準値を流し込む捏造**（総蛋白=6.5, LDH=229 等 → **False-Value 8件**）
  - 体脂肪率に BMI 値を転記（捏造・モデル自認）
  - rows 59→**120**、重複 7→**12** と膨張、しかも run 毎に「未実施→空(正)」と「未実施→基準を値に(捏造)」で**振れる**
- 値一致率は Markdown と同点。**納品のクリーンさ（余剰/誤り排除）で Markdown が上** → **既定 Markdown で確定**（JSON経路はコード温存）。

### (b) 決定論の後段整形を追加（LLM不変）
- **名称正規化**：`血圧|最高→最高血圧` 等、run毎に揺れる納品名を正準化（`血圧|最高` / `最高血圧|最高` / `血圧|最大血圧` を実測 → すべて `最高血圧` に収束）。照合器側も末尾「数/量/値」除去＋別名(alias)で吸収（白血球数↔白血球）。
- **定性サルベージ**：**免疫便潜血系のみ**、value 空時に基準列(ref_high)の `(-)` を value へ移送（名称スコープ限定で未実施行を誤埋めしない）。
- **脚注記号除去**：`(-)*`（紙面の星印）→ `(-)`。

### (c) 境界定性の2パス再読（Phase 1・ご助言の「疑わしい項目だけ再読」）
- 一次パスで**空だった境界項目だけ**（尿蛋白/尿潜血/尿糖/免疫便潜血/K-W）を、その画像へ**軽量シングルタスクで再読**しギャップ埋め。
- **既存値は上書きしない（numeric不変）／空返しは埋めない（捏造しない）／該当セクションが画像にある時だけ再読**。`temperature:0`。

### 最終メトリクス（🎯決定論ゴールデン・複数run）
- **numeric 全一致・安定**（身体計測/血圧/血算/脂質/肝/腎/尿酸/眼圧…）

- **残差＝免疫便潜血のみ**（後述）

## 2. 唯一の残差：免疫便潜血の「純粋検出漏れ」

人手ゴールデンでは 免疫便潜血反応 1日目/2日目 = **陰性(-)**（実施済）。ところが run により3挙動に割れる：

1. **正読**：value=`(-)`（正しい・多くの run）
2. **列取り違え**：value空、`(-)`が基準列(ref_high)へ → **決定論サルベージで復元**（対処済）
3. **純粋検出漏れ**：`(-)`を **value にも ref にもどこにも読まない**（下記 raw）。section を「尿検査」と誤ラベルし、結果欄も空。
   → salvage は移す元が無く不発（正しい）。**再読(temp0)も同じ画素を見て同じく空**。ここで補完すると**捏造**になるため**空のままにする**（＝我々の「捏造ゼロ」原則）。

実測 raw（挙動3の run・該当2行）:
```
| 尿検査 | 免疫便潜血反応 1日目 | (空) | (空) | (空) | (空) | (空) | - | - |
| 尿検査 | 免疫便潜血反応 2日目 | (空) | (空) | (空) | (空) | (空) | - | - |
```
※同じ画像でも別 run では正読される＝**検出が非決定**。他ページの numeric は全て安定して読める。便潜血だけが淡い/小さい定性記号で、Flash-Lite の検出閾値ギリギリに見える。

## 3. 制約（再掲）
- `temperature:0`（前回「temp は非決定の主因でない／3.xは依存小」との助言で据え置き）。ただし**同一画像の再読は temp0 だと同じ結果**になりがちで、検出漏れの救済に効きにくい。
- 1画像=1リクエスト・60s。キーは Vercel サーバ側のみ。
- **捏造ゼロが最優先**：人手ゴールデンが (-) でも、モデルが読まない値を後段で埋めることはしない方針。
- プロンプト肥大化は回帰の元（経験済）。
