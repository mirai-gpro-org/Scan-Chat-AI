## 3. Gemini の回答（要旨）と、実装側からの技術注意 —— ChatGPT に判定してほしい争点

Gemini は方針（Phase1=C+D 即時 / Phase2=A プロベナンス分離 / Phase3=B マルチRUN）を全面支持。加えて具体化を提示。**以下、Gemini 案（G:）と実装側の注意（注:）を並べます。ChatGPT の同意/反論をお願いします。**

### 争点1：C 視力/眼圧の値域再命名
- **G:** 数値かつ小数第1位0（10.0）または5〜30整数→眼圧 / 0.01〜2.0非テキスト→視力 / テキスト（異常なし）→眼底。聴力(右/左→1000/4000Hz)・尿定性の名称つぶれも同型で先回り。
- **注:** 「小数第1位0→眼圧」は**視力1.0も小数第1位0**で誤判定源。実際は**裸眼視力0.01〜2.0と眼圧5〜30はレンジが重ならない**（視力上限2.0<眼圧下限5）ので、**「数値は値域だけで一意＋テキスト→眼底」で足り、小数桁ルールは不要（むしろ危険）**。
- **→ ChatGPT へ:** この単純版で漏れる眼科系のコーナーケース（術後高眼圧が視力レンジに入る、矯正視力の混入、片眼のみ実施 等）はあるか。聴力/尿定性への横展開で、値域だけでは分離できない欄はどれか。

### 争点2：A 脂質シャッフルを「確定制約を破らず」救えるか
- **G:** ①プロベナンス（page2推移グラフ由来に `role:trend` を付与し current 配列から構造分離＝collision を発生させない）②Friedewald（TC≈LDL+HDL+TG/5）で回転検知。
- **注:** プロベナンス分離は**「選択でなく汚染除去」**として捏造ゼロと両立すると考える。ただし **Friedewald で"正しい組合せを選び直す"のは「同名異値の自動採用」に触れかねない**。安全側では、**Friedewald は"回転が疑われる行を UNRESOLVED としてフラグ（納品しない）"の番人に留め、自動で正解を作らない**べきと考える。
- **→ ChatGPT へ:** (a) プロベナンス分離を「捏造ゼロと両立」と整理してよいか。(b) Friedewald を"補正"に使うのは確定制約違反か、それとも「独立測定TCとの整合＝証拠に基づく確定」として許容されるか。(c) そもそも主パス出力に **page/section の来歴が安定して付くのか**（付かないなら A は B 側=多数決に寄せるしかない）。

### 争点3：B マルチRUN多数決の設計
- **G:** N=3・2/3クオラム・同一性キー=`section_index＋値近似`・割れたら EXHAUSTED_UNRESOLVED・適用順=多数決→正準化→プロベナンス/dedup→会計/VQA。
- **→ ChatGPT へ:** (a) 名称が崩れる前提で `section_index＋値近似` を同一性キーにすると、**シフト自体が section_index をずらす**場合に多数決が崩れないか。より頑健なキー（期待項目テンプレの位置アンカー等）はあるか。(b) N=3 で「毎回別の行がずれる」タイプの非決定に対し、2/3 が本当に成立するか（各行独立にシフト確率が低ければ成立するが、相関シフトだと崩れる）。(c) コスト3倍に見合うか、それとも A/C/D で 85% まで上げてから B は温存が妥当か。

### 争点4：Q5 セクション単位の脱落検知

- **→ ChatGPT へ:** マスタ側に「セクション別 期待件数」を持たせる必要があるが、様式差（実施項目が施設で異なる）で**過検知（未実施セクションを脱落と誤認）**しないか。閾値でなく「見出し検出∧そのセクションの充填率」で見るべきか。
