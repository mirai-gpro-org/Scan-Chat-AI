# 【ご相談】検査票スキャンの定性結果 (-) が run 毎に脱落する問題 — 改善案のご意見をください

医療検査票を写真から構造化するシステムの、**定性項目の非決定な取りこぼし**についてご意見を伺いたく、
背景・確定制約・既に試した施策を添えます。**「基準値は保持する」前提**で、実装可能な改善案をお願いします。

---

## 1. システム前提（動かせない設計）

- **役割**: このコンポーネントは「検査票の画像 → 忠実な転記」だけを担う（Perception専任）。
  臨床判断・整形は下流の別AI／後段の決定論プログラムが行う。**LLMに判定・整形はさせない方針**。
- **モデル**: **Gemini flash-lite** を常用。上位の Flash は混雑時 503(model overloaded) が頻発し
  バッチ全滅の実績があるため常用不可（**モデル格上げは非現実的**）。
- **解像度は主因ではない**: 数値(numeric)は run 間で全一致・決定論的に読めている。
  取りこぼすのは定性項目だけで、しかも run 毎に入れ替わる（＝ピクセル不足では説明できない非決定）。
- **レイアウト非標準**: 検査機関ごとに帳票デザインが異なり変更もされる前提。固定テンプレOCRは不可、
  だからマルチモーダルLLMを採用している。
- **出力は Markdown ファースト**（responseSchema は最小）。列は概ね
  `No | 検査項目 | 検査項目詳細 | 読み取った値(=今回) | 推論値 | 単位 | ref_low | ref_high | 判定(flag) | 備考`。
- **時系列は「今回」列のみ採用**（前回・前々回は出力段階で捨てる）。今回が空なら空（過去値の繰り上げ禁止）。

## 2. 課題（今回のフォーカス）

**定性項目**（免疫便潜血反応・尿蛋白/尿潜血/尿糖・K-W分類 等）の結果 `(-)` が、
**run 毎に非決定で value 空になり、納品から脱落する（Missing）**。

**真因＝Semantic Tie（同一トークンの列取り違え）**:
検査票の同じ行に「**基準列の (-)**」（陰性が正常＝基準表記）と「**今回結果列の (-)**」が並ぶ。
両者は視覚的に同一の `(-)`。モデルはどちらを結果(value)、どちらを基準(ref)に入れるか判別しきれず、
**結果の (-) が基準列(ref_high)へ吸われ、value が空**になる run が発生する。

**具体例（実際の検診票）**:
- 免疫便潜血反応 1日目/2日目: 基準列も `(-)`、今回結果も `(-)` → run により value 空。
- 尿蛋白/尿潜血/尿糖: 同様に 基準 `(-)` と 今回 `(-)` が並ぶ。

### Markdown 出力サンプル（列スキーマ準拠・故障パターン再現）

> 注: 下記は本システムの**実際の出力列スキーマ**と、**実測された故障パターン**に忠実に再現した代表例です
> （キー保護のためこの場で特定 run のバイト列は再現していません。列構成・症状は実データと同一）。

実際の列は次の通り（`読み取った値` が今回の結果、`ref_low`/`ref_high` が基準値）:

```
| No | 検査項目 | 検査項目詳細   | 読み取った値 | 推論値 | 単位 | ref_low | ref_high | 判定 | 備考 |
|----|----------|----------------|--------------|--------|------|---------|----------|------|------|
```

**(A) 正常に読めた run（結果 (-) が value に入っている＝正解）**
```
| 32 | 糖代謝   | 尿糖           | (-)          | -      | -    | -       | (-)      | -    | -    |
| 41 | 検便     | 免疫便潜血反応1日目 | (-)      | -      | -    | -       | (-)      | -    | -    |
```

**(B) 故障した run（Semantic Tie＝結果 (-) が基準列 ref_high へ吸われ、value が空）**
```
| 32 | 糖代謝   | 尿糖           | -            | -      | -    | -       | (-)      | -    | -    |
| 41 | 検便     | 免疫便潜血反応1日目 | -        | -      | -    | -       | (-)      | -    | -    |
```

(B) では `読み取った値`(value) が空 `-`、`ref_high` に `(-)`。後段は value 空を「未実施」とみなし**納品から除外＝Missing**。
同一画像・同一プロンプトでも run により (A)/(B) が入れ替わる（**非決定**）。基準列にも今回列にも同じ `(-)` が
並ぶことが原因で、どちらを value に採るかが安定しない。**(A) と (B) を安定して (A) に寄せたい**（ただし基準の
`(-)` を今回結果として value に流し込む捏造＝False-Value にはしない）。

## 3. 確定制約（この前提で案をください）

1. **基準値(ref_low/ref_high)は保持する**（削除前提の案は不可）。
2. **捏造ゼロ**: 今回が空欄なら空のまま。基準値を結果として value に流し込むのは厳禁（最重要の誤り）。
3. **numeric を壊さない**: 数値項目は既に全一致で安定。これを劣化させない。
4. **モデル格上げ・高解像度化は不可**（503／主因でない）。flash-lite + Markdown 前提。
5. **後段は決定論プログラム**（プロンプトで判定させない設計は維持）。

## 4. 既に試した施策（結果つき）

| 施策 | 内容 | 結果 |
|---|---|---|
| **responseSchema(JSON)化** | value / ref_high を別フィールドに固定し列ズレを構造的に断つ狙い | ❌ **逆効果**。未実施行の value に基準値を流し込む **False-Value(捏造) が多発**（実測8件）。不採用、Markdownに戻した |
| **定性サルベージ（後段・決定論）** | value 空のとき、`(-)/(+)/陰性/陽性` を ref_high/ref_low/note から value へ移送。**便潜血系のみ**に名称限定（他項目の「基準=(-)」を結果と誤読しないため） | ✅ 採用。ただし便潜血限定で、汎用化すると誤救済リスク |
| **境界2パス再読** | 一次パスで空だった定性行だけ、その画像へ軽量シングルタスクで再読しギャップ埋め（既存値は上書きしない・空返しは埋めない） | ✅ 採用。残差＝稀に「モデルが (-) を value にも ref にも読まない純粋検出漏れ」 |

## 5. 伺いたいこと

**「基準値は残す・捏造ゼロ・numeric非破壊・flash-lite+Markdown」の制約下**で：

1. **Semantic Tie の分離策**: 「結果の (-)」と「基準の (-)」を、プロンプト設計／読み取り順序／
   Markdown の列表現などで**安定して区別**させる具体案は？（responseSchema以外で）
2. **後段の決定論ルール**: 便潜血限定でなく**定性項目全般**に効き、かつ「基準=(-)」の未実施行を
   誤って埋めない、安全な列サルベージ規則の設計は？（判定条件・スコープの切り方）
3. **非決定性の低減**: flash-lite で定性検出の run 間ブレを減らす実務的手法
   （プロンプト、few-shot、行型のヒント、再読の掛け方 等）。
4. **検証観点**: 決定論ゴールデン照合で **Missing / Column-Shift(過去値の今回混入) / False-Value** を
   見ているが、この問題に有効な追加の回帰指標・エッジケースがあれば。
