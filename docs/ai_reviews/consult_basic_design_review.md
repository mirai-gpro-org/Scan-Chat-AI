# 相談（第3回）: 「基本設計」そのものの見直し依頼 ― 改善後の設計が当初見込みに応えていない

健診票（紙）を **Gemini マルチモーダルで読取 → 構造化 JSON → 外部連携（Elith 社の AI 診断）** に渡すパイプラインを運用しています。
第1回（run間 非決定性）・第2回（最後の定性1項目の検出漏れ）のご助言に沿って改善を重ね、**「numeric は安定・残差は定性1項目のみ」＝実用ほぼ完成**と判断していました。
ところが本番相当の直近 RUN で、**これまで安定と見なしていた numeric（数値）項目が 1 件サイレントに脱落**しました。医療データで **40 項目弱のうち 1 項目欠落は致命的**です。
**改善策の積み上げではなく、基本設計そのものの妥当性**を、**ゼロベース**で評価・再提案してください。

---

## 0. 何を依頼したいか

1. **設計思想を変更してきた経緯（§2）と、その結果できた基本設計（§3）が、当初ゴール（§4）に照らして妥当か**、忌憚のない評価。
2. **numeric 項目が疎なページで脱落する根本原因の見立て**（判断材料は §5 の事実のみ）。
3. **基本設計レベルの改善案を、ゼロベースで提案**（＝小手先のプロンプト調整でなく、パイプライン構造・検証層の設計）。
   - **当方の案・仮説は提示しません。先入観なく独自にご提案ください。** ただし §6 の「却下済み手段」は既に実証的に不採用のため、そこは踏まないでください。

> 本文書は**事実のみ**を記載します（当方の原因推測・改善案は意図的に排除）。

## 1. システム前提（事実）

- **モデル**: `gemini-3.1-flash-lite`（上位 flash は混雑時 503 でバッチ全滅の実績があり据え置き）。native multimodal・REST・`temperature:0`。
- **実行環境**: Vercel Serverless（関数 ~60s）。**1 画像 = 1 リクエスト**でクライアントが 5 枚を順に呼ぶ。
- **入力**: 健診票 5 枚。ページにより密度が大きく異なる（血液・脂質ページは高密度、血清/脈波/肺機能/痛風/肝炎ページは大半の欄が空）。
- **出力**: ページごとに **10 列 GFM テーブル(Markdown)** → 後段の**決定論プログラム**でパース＆正規化 → JSON。
  - 列: `No | 検査項目 | 検査項目詳細 | 読み取った値 | 推論値 | 単位 | 下限値 | 上限値 | 判定 | 備考`
- **時系列の仕様**: 検査票は「今回 / 前回 / 前々回」が横に並ぶ。**採用は「今回」列のみ**（今回が空欄ならその項目は空。前回値を繰り上げない）。
- **品質測定**: 人手確定した「今回」値の**ゴールデン**と、生成 JSON を**項目単位で決定論照合**（一致率 / Missing / Column-Shift / Wrong / False-Value）。この照合は**検証用ツール**であり、本番納品経路には含まれない。

---

## 2. 設計思想を「変更」してきた経緯（事実・時系列）

1. **初期思想**: 「検査票のレイアウトは機関ごとにバラバラで統一標準が無い → **native multimodal で読む。OCR/レイアウト・パターンマッチ（テンプレOCR）は使わない**」。読取は LLM に一任、後段はごく薄い整形のみ。
2. **課題の発生**: 同一画像・同一プロンプトでも **run 毎に定性/境界項目の列帰属・空欄判断が揺れる**（第1回相談）。「今回=空が正の項目に過去列の値が混入する（時系列軸リーク）」も発生。
3. **思想の再位置づけ（意図的変更）**: 「**最終ゴール（正確な JSON＝漏れなし・捏造なし・余剰なし）が最上位。設計思想（native multimodal / パターンマッチ禁止）は手段であって従属。ゴールに得点できないなら手段を変える**」と明文化。
4. **その下で積み上げた対策（事実）**:
   - **決定論の後段整形**（LLM に判定・整形をさせない）: 名称正規化（`血圧|最高→最高血圧`, `白血球↔白血球数`）、単位/判定正規化、空行(未実施)除外、総合判定欄除外。
   - **定性サルベージ**（決定論）: value 空時に基準列へ吸われた `(-)` を value へ移送（名称 allow-list 限定）。
   - **VQA 第2パス（Verify & Repair）**: 一次パスは不変のまま、**疑わしい項目だけ**を局所再読。
     - Phase1: 定性/境界（尿蛋白/尿潜血/尿糖/免疫便潜血/K-W）の空欄充填・許可集合外トークンの上書き（捏造ゼロの fail-safe 付き）。
     - Phase2: 時系列軸リーク（眼圧・血清等「今回=空が正」の項目）の過去値混入を削除。
   - **json mode(responseSchema) は検証の上で不採用**（未実施欄に基準値を流し込む補助欄暴走=False-Value、行数・重複膨張。Markdown 版で確定）。
   - **②正準化層（KMAT 健診標準フォーマットへの決定論マッピング）**: 名寄せ・単位・判定の統一、余剰/不足の判定（読取値 numeric には触れない）。
   - モデル格上げ（3.1-lite→3.5）は md 段階で lite を上回らず・503 リスクで不採用。
5. **結論（当時）**: 決定論ゴールデンで **numeric 全一致・False-Value 0・Column-Shift 0**、残差は **免疫便潜血の稀な検出漏れ 1 項目のみ**（捏造ゼロのため空のまま運用）＝**実用ほぼ完成**と判断。

**現在の設計思想の要約: 「LLM は高精度パーサに限定し、検証・正規化・救済は決定論コードと局所 VQA で行う。読取①のプロンプトは凍結（凝ると回帰する実績）。」**

---

## 3. 現在の基本設計（事実）

```
[5枚の画像] 
   ↓ ①読取(native multimodal, gemini-3.1-flash-lite, 10列Markdown, temp0)  ← プロンプト凍結
[生Markdown表]
   ↓ 決定論パース + 後段整形(名称/単位/判定正規化, salvage, 空行除外)
   ↓ VQA第2パス(定性充填 / 時系列リーク削除)  ← 「疑わしい項目だけ」局所再読
   ↓ ②正準化(KMAT標準マスタへの決定論マッピング: 名寄せ/単位/余剰・不足)
[Elith納品JSON]
```

- 完全性(漏れなし)を守っている層は **VQA と salvage** であり、**その対象は "定性 / 境界 / 時系列リーク" に限定**されている。**numeric の取りこぼしを検知・回復する層は存在しない。**

## 4. 当初ゴールと「見込み」（事実）

- **最終ゴール**: 正確な JSON（**①漏れなし ②捏造なし ③余剰なし**）→ Elith → 高精度診断。
- **改善後の見込み**:
  - numeric は **run 間で全一致・安定**（第1回相談の実測: 同一5枚×2run で **numeric 29/29 両 run 一致**）。
  - 残るは **定性 1 項目（免疫便潜血）の検出限界のみ**。
  - **捏造ゼロ**（モデルが読まない値を後段で埋めない）。

## 5. 現状：見込みに応えていない事象（直近 RUN の実測・事実のみ）

同一様式の健診票（受診日 2025-01-23）で、**numeric 項目が 1 件サイレント脱落**した。

### 5.1 ゴールデン照合結果（この RUN）
```
今回値一致 31/34 (91%)  Missing 3 / Shift 0 / Wrong 0 / False-Value 0
定性一致 5/7 (71%)      Semantic-Tie(残) 0
Missing(今回値の取りこぼし):
  ・尿酸 期待=7.8                  ← numeric
  ・免疫便潜血反応 1日目 期待=(-)   ← 定性（第2回相談で既知の残差）
  ・免疫便潜血反応 2日目 期待=(-)   ← 定性（第2回相談で既知の残差）
VQA再読: 充填0 / 上書き0 / 削除2(眼圧右/左 timeline_leak) / 未解決3 / エラー0
```

### 5.2 尿酸の真値（**元画像を目視確認済み**）
画像の列は `基準値 | 今回 | 前回 2023/4/22 | 前々回 2020/8/3 | 単位`。尿酸行:

| 今回 | 前回(2023/4/22) | 前々回(2020/8/3) | 単位 |
|---|---|---|---|
| **↑ 7.8** | ↑ 7.7 | 6.9 | mg/dl |

今回列に赤↑付きで **7.8** が印字されている（実施済・空ではない）。

### 5.3 生 Markdown（この RUN の該当行）
```
| 痛風 | 尿酸 | 読み取った値=(空) | 推論値=(空) | mg/dl | 2.1 | 7.0 | 
   備考=【要確認】今回欄に値なし。前回7.8(H), 前々回7.7(H)と記載あり |
```
- 一次読取(①)の「読み取った値」列が空。7.8 は**備考テキスト内に「前回7.8」としてのみ存在**し、構造化された今回値としては入っていない。
- したがって後段の決定論整形も②正準化も回復できない（渡ってくる今回値が空）。**脱落は md（一次パス）段階で発生している。**

### 5.4 その他の観測事実（因果の解釈は付さない）
- 該当ページ（③-4：血清/脈波/肺機能/ABC/痛風/肝炎）は、**今回列の大半が空欄**。今回列に値がある行は **尿酸 / 免疫便潜血1日目 / 免疫便潜血2日目 の 3 行のみ**。
- **この RUN では、その 3 行すべてが脱落**した（尿酸=Missing、免疫便潜血×2=Missing）。
- 今回列には**ヘッダ日付が無い**。前回列・前々回列にはそれぞれ **2023/4/22・2020/8/3** の日付ヘッダがある。
- **同一画像・同一設定でも、別 RUN では numeric を正読する**（第1回相談時の実測で numeric 29/29 が両 run 一致）。すなわち numeric の列帰属・読取も非決定でありうる。

### 5.5 なぜ致命的か（事実）
- 医療データで、40 項目弱のうち **1 項目のサイレント脱落**は診断精度・安全性に直結する。
- 「numeric は安定」という**基本設計の前提が崩れている**。
- 完全性を守る層（VQA/salvage）は定性/timeline のみを対象とし、**本番経路に numeric 脱落を検知する層が無い**（ゴールデン照合は検証用ツールで、本番納品には含まれない）。

## 6. 制約・却下済みの手段（**提案時に踏まないでください**・すべて実証済み）

- **主パス(一次プロンプト)の強化・列アンカリングの作り込み = 不採用（回帰実証済み）。** 「今回列を確実に取らせる」ため 3 列スペーサ方式を作り込んだところ、狭いマーカ(↑↓)列付近で 1 列右シフトが起き、身体計測/血圧/視力が壊れて全リバート。時系列規則や O/X 列の追加も同様に numeric を壊した。→ **①読取のプロンプトは凍結**が前提。
- **json mode(responseSchema) = 不採用**（未実施欄に基準値を流し込む補助欄暴走=False-Value、行数・重複膨張）。
- **モデル格上げ(3.5) = 不採用**（md 段階で lite を上回らず・503 リスク）。
- **人手確認を"納品ゲート"にする = 不採用**（Elith 納品の完全性を人手承認で担保する運用はスケールせず、全自動というゴールに反する）。
- **温度を上げる/seed 固定**は第1回助言で temp0 据え置き（同一画像の temp0 再読は同結果になりやすい点は把握済み）。

## 7. 聞きたいこと（効果が大きい順に・基本設計レベルで）

1. **総括評価**: §2 の設計思想変更（LLM=高精度パーサに限定 / 決定論コード＋局所 VQA で検証・救済 / 読取プロンプト凍結）という基本設計は、当初ゴール（漏れなし）に対して妥当か。**「numeric は安定」という前提に依存した設計が疎ページで崩れた**のは構造的欠陥か、運用でカバーできる範囲か。
2. **根本原因**: §5 の事実から、numeric が疎ページで脱落する原因の見立て。**①のプロンプトを凍結したまま** numeric の列帰属・完全性を安定させる筋の良いレバーは何か。
3. **基本設計の改善案（ゼロベース）**: **捏造ゼロ・主パス不変・1画像1req/60s・追加依存最小**の制約下で、効果が大きい順に 3 つ。読取と検証の責務分界の引き直し、完全性を保証する層の置き方、疎ページ専用経路の是非など、構造レベルで。
4. **完全性の保証方法**: 「画像にあるのに JSON に無い」を**捏造せずに**必ず検知・回復するアーキテクチャは何か。それぞれの落とし穴。
5. **止め時と投資判断**: numeric の稀な列シフトを潰すための追加コスト（画像処理・多重読取等）をどこまで許容すべきか。医療データの「1 項目脱落の許容度」を設計にどう織り込むべきか。
