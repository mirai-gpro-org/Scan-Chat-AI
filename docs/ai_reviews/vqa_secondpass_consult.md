# 【ご相談】主パス補強が numeric 回帰した件と、第2パスVQA(対策C)の設計

前回いただいた助言（主パス不変・第2パスVQA・定性サルベージ一般化）に沿って実装・検証を進めた結果、
**「時系列軸リーク（今回の False-Value）」を主パスのプロンプト補強で直そうとしたら numeric が回帰**しました。
経緯と実データを共有し、**第2パスVQA(対策C)の具体設計**についてご意見を伺いたいです。

---

## 0. 前提（不変の制約）
- LLM=Perception専任（忠実転記）。判定/整形は後段の決定論プログラム。診断は別AI(Elith)。
- モデル=**Gemini flash-lite**（上位Flashは503頻発で常用不可）。出力=**10列Markdown（主パス）**。
- **主パスは不変が原則**（numeric非破壊が最優先。responseSchema/JSON化は補助欄暴走で不採用済み）。
- **基準値は保持・捏造ゼロ（今回が空なら空）・追加依存なし（画像処理ライブラリ不可）**。
- 検証=決定論ゴールデン照合（🎯）。同一検体1人分(検診5枚)で Missing/Shift/Wrong/False-Value を測る。

## 1. 問題は2クラスある（どちらも run毎に揺れる＝非決定）
- **クラスA：定性 Semantic-Tie**：結果 `(-)` が「基準列」に吸われ今回値が空→脱落(Missing)。対象=尿定性/便潜血。
- **クラスB：時系列軸リーク**：今回=空が正の行で、モデルが**前々回の孤立値を今回列に混入**（False-Value）。
  対象=**眼圧（前々回16）／眼底その他（前々回「視神経陥凹」）／血清 RPR・TP抗体（前々回(-)）**。
  ※ raw_markdown 実測で「読み取った値」列に過去値が入る＝**主パス起因**。後段は過去列を持たず修正不能。

## 2. 試したこと（対策A＝主パスのプロンプト補強）と結果＝numeric回帰
主パスの【時系列列の扱い】に「**孤立した過去列値の混入禁止**（前回/前々回にしか値が無く今回が空なら今回は空。
疎ページ対策は"今回列の実在値"を守る指示であって過去列孤立値を今回へ繰り上げる根拠にしない。眼圧/RPR例を明記）」
を追記した。

**🎯結果（同一検体・4 run）**:
| run | 変更 | 一致 | Missing | Shift | Wrong | False-Value | 備考 |
|---|---|---|---|---|---|---|---|
| 1 | (基準) | 32/34 | 0 | 0 | 2 | 2 | Wrong=免疫便潜血1/2日目 空欄 / FV=眼圧右左16 |
| 2 | (基準) | 34/34 | 0 | 0 | 0 | 2 | FV=眼圧右左16（免疫便潜血は今回読めた） |
| 3 | **対策A投入** | **25/34** | **9** | 0 | 0 | **0** | **FV=0 になった一方、身長/体重/標準体重/BMI/腹囲/最高血圧/最低血圧/裸眼右左 が Missing** |
| 4 | **A撤回** | 32/34 | 0 | 0 | 2 | 4 | Wrong=免疫便潜血=「1」/ FV=眼圧右左16・眼底その他右左=視神経陥凹 |

**learnings**:
- 対策A は **False-Value=0 を達成したが、Missing=9 の numeric 回帰**を招いた。消えた9項目は全て
  **「今回・前回・前々回が3列とも値で埋まっている行」**（身体計測/血圧/視力）。flash-lite が
  「過去値を採るな」を過剰適用し、**どれが今回か迷って行ごとドロップ**したと解釈。→ **即撤回**。
- **結論：主パス(プロンプト)への時系列規則の強化は flash-lite で numeric を壊す**（責務分離の原則どおり、
  主パスは触らないのが正解と再確認）。
- 撤回後（run4）は numeric 復旧（Missing0）。残るのは**非決定な**時系列軸リーク(眼圧/眼底その他=FV4)と、
  **免疫便潜血の誤読「1」**（(-)を"1"と読む＝値の誤読。空でも leak でもない別種）。

## 3. 収束方針＝第2パスVQA(対策C)。ただし設計判断が要る
主パス不変のまま、`SCAN_BOUNDARY_RECHECK`（一次パスで空だった項目だけ軽量再読する既存経路）を
**局所VQAへ格上げ**し、以下2つを1機構で扱いたい：
- **(a) 検出漏れ補完（クラスA）**：今回が空の定性行に「結果セルに印字はあるか」をVQAし、`(-)/(+)` 明言時だけ埋める。
- **(b) 時系列リークのドロップ（クラスB）**：今回=空が正の疑い行に「今回セルは空か」をVQAし、**空確認時だけ
  後段で過去混入値をドロップ**（値→空）。

## 4. 伺いたいこと（設計の要）
**Q1. スコープの決め方**：全項目にVQAは非現実的。**(a)は定性 allow-list**（尿定性/便潜血）、**(b)は「今回=空が
正となりやすい項目リスト」**（眼圧/眼底その他/血清定性/ABC/肺機能等）に限定する想定。この**対象リストの安全な
決め方**（誤爆＝正常な今回値を空判定して落とすリスクを最小化する基準）をどう設計すべきか？

**Q2. 上書き/ドロップの線引き**：捏造ゼロ・誤削除最小の観点から、
- **許可**：value空→(-)充填（a）／過去混入値→空へドロップ（b）。
- **禁止**：value→別value の上書き。
という線引きを想定。**この方針で妥当か**？ また **免疫便潜血=「1」のような"値の誤読"**は、この
「上書き禁止」方針では拾えない。これを安全に是正する方法はあるか（例：定性項目は結果集合を
`{(-),(+),(±),陰性,陽性,0}` に限定し、集合外(“1”等)はVQA再読の対象にする 等）？

**Q3. (b)のドロップで新たな Missing を出さない担保**：VQAが「今回空」と誤答して**本当は在る今回値を落とす**と
新規Missingになる。**高信頼のときだけドロップ**するための判定（3択の完全一致のみ採用／過去列値と一致する場合のみ
ドロップ／2回一致 等）の推奨は？

**Q4. VQAプロンプトの型**：クラスBは「今回セルに印字があるか無いか」を、基準や過去列の存在を**宣言(グラウンディング)**
した上で3択（結果=印字あり:値 / 完全空欄 / 不明）で返させる想定。クラスAと同じ型で両対応できるか、分けるべきか？

**Q5. クロップ前処理**：画像処理ライブラリ不在（追加依存なし方針）・キーはVercel側・関数60s制約。
サーバ側ピクセルクロップは非現実的だが、**行ROIに絞る代替**（bboxは領域単位のみ保持、行bboxは無い）で
VQA精度を上げる現実解はあるか？（無ければフル画像＋テキストで行を指定するVQAで十分か）

## 5. やってはいけない（実証済のアンチパターン・確認）
- 主パスの列追加（O/X等）→ numeric回帰リスク（却下済）。
- 主パスの時系列規則の強化 → **今回 numeric回帰（Missing9）を実測**（撤回済）。
- responseSchema/JSON化 → 補助欄暴走（False-Value）で不採用。
- 基準(-)→value 自動コピー → False-Value。

以上を踏まえ、**第2パスVQA(対策C)を"検出漏れ補完＋リークのドロップ"の両対応で安全に組む設計**について、
実装しやすい形（プロンプト規約・後段の採用条件・スコープ決定則）でご提案ください。代表として検診5枚
